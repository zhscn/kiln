# MIR：Lisp 语义中端

状态：**实验框架已接入**。生产编译仍使用 HIR → LIR；MIR 通过显式入口构造 CFG、验证 SSA 并输出同一套 LIR。HIR 求值器和已有优化保留原来的路径。分层和迁移见 [compiler.md](compiler.md)。

MIR（mid-level IR）由 Lisp 从 HIR 构造，是控制流图加 SSA。它负责 Lisp 程序的分析、优化和表示选择，最后退出 SSA，输出 [LIR](lir.md)。MIR 不是通用的低级 SSA：对象身份、闭包、可写捕获、多值和动态范围在 MIR 里仍是可辨认的操作。机器层的通用优化留给 Cranelift。

## 当前框架与入口

树上的绑定读写不能直接作为 SSA 使用，循环回边和条件合流必须给每条进入边
提供变量的当前版本。当前构造器为每个函数单独编号绑定，在非入口块上为全部
局部绑定建立参数；需要表达式结果的合流块再带一个多值 bundle 参数。每条边
显式传入完整绑定状态，因此回边和交换赋值也服从同一规则。尚未删除冗余块参数，
这使初始构造简单、可验证，代价是图和边的实参数量较大。

实现分为 `lisp/mir/data.lisp`、`verify.lisp`、`build.lisp`、`lower.lisp`、
`types.lisp`、`calls.lisp` 和 `dump.lisp`。编号索引复用可增长向量容器，语义值表示为 `obj`、`bundle` 和
参数计数 `count`；LIR 发射时将 bundle 实现为保存载体和个数。跨调用的多值先保存，
取主值和函数返回时再恢复，避免借用的多值传递区被后续调用覆盖。

已支持常量、非捕获局部绑定与赋值、全局变量和函数 cell、无捕获函数及局部函数组、普通调用、
原语调用、`if`、顺序形式、函数内 `block`/`return-from` 与 `tagbody`/`go`、
`multiple-value-prog1` 和单值类型检查。函数入口支持必需参数并检查数量。
值保持装箱，类型声明重新生成检查，再由 MIR 的类型事实证明是否可以省略；
HIR 的区间、逃逸、栈存储和拆箱证明不导入 MIR。
指令和终结点保留源码位置与策略，运行期变量帧映射尚未接入。

动态区域、跨函数退出、捕获闭包、optional/key/rest 参数、
load-time values、多值绑定及 `multiple-value-call` 尚未接入；构造器发出
`mir-unsupported` 编译条件，调用者不会收到部分代码。生产路径的切换仍按
[compiler.md](compiler.md) 的语义与性能门槛进行。

- `hir-to-mir` 接受一个 HIR 函数，返回已验证的函数单元。
- `verify-mir` 检查编号所有权、边参数、表示、效果下界、入口数量检查及 SSA 支配关系。
- `print-mir` 输出编号、块参数、操作、效果、源码和策略，供调试查看。
- `compile-module` 的 `:pipeline :mir` 为显式文件模块入口；默认是 `:hir`。
- 运行期动态绑定 `kiln.compiler::*compiler-pipeline*` 为 `:mir` 后调用原生 `compile`，
  只选择本次函数编译。转换期间内部生成的编译器辅助函数继续使用生产路径。
  `eval`、`load`、缓存及 FASL 保持原有入口。

`mir-analysis` 按函数修订号缓存一个分析结果。结构变换通过 `mir-run-pass`
执行：先增加修订号，清除没有列入 `:preserves` 的分析，再运行变换并验证结果。
默认不保留分析；pass 必须对明确保留的事实负责。当前验证器计算可达性和支配关系，
基础类型、算术区间与条件边传播及局部调用返回摘要已接入；存储选择尚未迁移。

`mir-infer-types` 按 SSA 值编号缓存主值类型。常量和函数对象提供初始事实，
赋值、单值 bundle 和取主值操作传递事实，块参数汇合所有可达前驱的实参类型。
固定点迭代覆盖循环回边，不可达前驱不参与合流。CL 标准函数的类型规则接收
实参的 SSA 类型，推导二元算术、增减、位运算和部分容器操作的主值类型；
`values` 和 `identity` 转发主值事实。类型域、函数规则与声明证明在
`lisp/type-inference.lisp` 中由两条路径共用，不读取 HIR 节点的推导标记。

条件边将测试所证明的事实传给目标块参数。谓词为真的边使用 CL 标准谓词的
类型；直接测试值为假的边将该值的主值收窄为 `null`。整数比较在两侧均有有限
区间时，按 `<`、`<=`、`>`、`>=` 和 `=` 的结果收窄对应操作数，真、假两条边
分别处理；反转操作数时也反转比较方向。无法表示的差集和不可能边仍保留保守
事实，不在此阶段删除控制流。

这些事实绑定到被测试的 SSA 值，而不是变量名。分析沿单值包装、取主值和声明
检查追溯主值身份，再与边上的实参匹配。测试之后发生赋值时，新值有另一个
SSA 编号，不会继承旧值的分支事实；合流块仍汇合所有可达前驱。未知谓词和
image 中可重定义的函数不提供条件事实。

算术运算会让循环中的整数区间不断扩大，因此每个 SSA 值在区间第二次扩大时
扩宽为 `integer`。事实只会变宽，后续传递不能把它收窄回有限区间；越过有符号
64 位边界的计算也退到 `integer`。这保证迭代收敛，代价是多次合流也可能丢失
区间精度。类型事实只用于已经完成固定点迭代的图。

声明检查接收一个 `obj` 或 `bundle`，返回同表示的新 SSA 值。分析在检查结果上
求输入类型与声明的交集，原来的输入值保持原有事实，因此检查后的类型不会
影响更早的使用处。参数绑定、局部初始化和赋值使用检查结果，`the` 返回检查后
的 bundle。bundle 的检查只约束主值，仍保留原来的返回值个数和其他值。

LIR 发射前使用完整固定点结果省略已证明成立的声明检查。需要执行 bundle
检查时先恢复主值供 `typep` 使用，再转发原先保存的载体与个数；检查调用可能
覆盖借用的多值区，不能从那里重新构造返回值。验证器要求检查的输入输出表示
相同，类型事实只属于检查正常返回的结果。

`mir-function-identities` 在 SSA 上跟踪局部函数编号。函数对象提供身份，赋值、
主值包装、声明检查和 CL 的 `identity`、`values` 转发身份；块参数的所有前驱
必须同意同一个编号，否则结果为未知。无词法数据捕获的 `flet`、`labels` 可以
直接使用这些函数的静态对象；对同组函数名称的引用不需要捕获槽。引用普通
词法数据的函数仍须等待闭包构造接入。

`mir-infer-calls` 根据已知目标建立调用图，按 SCC 顺序反复求参数和主值返回
摘要。实参从 caller 流向 callee，返回类型沿相反方向流动，因此遍历各组直到
两者共同稳定。参数汇合所有数量正确的已知调用点，不为单次调用单独特化；
数量错误的调用仍在读取参数前退出。递归参数和返回值的整数区间在第二次
扩大时退到 `integer`。没有事实种子的参数和返回值退到未知，再闭合一次固定点，
之后才发布优化事实。LIR 发射使用 `mir-infer-types` 的 unit 参数消费这些结果。

局部函数可能经函数值从别处调用，不能只根据具名调用点收窄其参数。
分析用位集合跟踪 SSA 值及 bundle 中可能携带的局部函数，合流取并集，
`values` 包括每个返回值，取主值时保守保留整个集合。返回、全局写、声明检查、
普通调用的实参、原语实参和未知目标调用的 callee 都使其中的函数具有外部
调用入口；这些函数和 unit 的入口参数从未知开始。当前不在函数间传播参数
的函数身份，也不展开堆容器，所以传给已知 callee 或容器构造器的函数同样
按外部入口处理。普通 `identity`、`values` 只转发值，可继续跟踪。
这些集合用于判定参数入口是否封闭；存储选择还需跟踪堆字段、捕获和对象生命周期，
建立独立的逃逸证明。

跨函数缓存同时记录 unit 中每个函数的对象身份与修订号。增加、替换或修改
callee 都会使整个调用分析失效，不能只凭 caller 的修订号复用其类型表。
返回摘要只提供类型事实，调用仍保留原来的效果、参数数量检查和多值协议。

外部入口未经检查的参数、全局读、未知目标的间接调用、image 定义的全局调用和原语
调用结果保持未知。活 image 中的全局定义可变，使用其摘要需要守卫或依赖记录。
bundle 只记录主值类型事实，未知调用也涵盖零个返回值时的 NIL。多值个数、
逐个返回值的摘要和跨调用函数身份仍待迁移。发射器不修改图。

退出 SSA 时为每条边建立独立的复制块，先把所有来源复制到临时量，再写入目标
块参数。这覆盖临界边、自回边和复制环；bundle 的载体及个数一起复制。
所有块入口发射 poll，以覆盖回边；Rust 后端继续负责 ABI、多值载体和精确 GC roots。

模型测试见 `tools/test-mir.lisp`，运行方式与 HIR 模型测试相同。
`tools/test-mir-lir.lisp` 使用 `tools/test.sh` 已生成的 kernel、CLOS 模块，验证
SBCL 从显式 MIR 入口生成二进制 LIR 并交给 JIT 执行。端到端用例在
`tests/m6/co-mir.lisp`，覆盖循环中的并行复制、多值跨调用保存、声明检查、参数数量
和未支持形式的失败路径。

以下各节描述 MIR 扩展到完整语义中端后的契约。

## 数据模型

函数、基本块、指令和值使用紧凑的整数编号，存在按编号索引的 simple-vector 里；节点本身是原生结构对象（[hir.md](hir.md) 的“原生的结构对象”），指令按整数 kind 分派。集合用位集合，工作队列用可增长向量。这些也是 [compiler-performance.md](compiler-performance.md) 要推的做法。

- 基本块参数表达 SSA 合流，终结指令列出全部后继和边上的实参。
- 绑定（HIR 的变量身份）、源码位置、策略和 SSA 值分开编号；循环里的一个分配点不代表所有动态对象是同一身份。
- 只有标量走 SSA。可变的堆字段、闭包共享的 cell、函数 cell、special 变量和动态环境保留显式的操作；起初不做 Memory SSA。
- 语义类型和机器表示分开：一个值可以有整数区间事实，同时仍是装箱的 `obj`。

分析结果放在侧表里，带函数的修订号。修改 CFG、调用或存储的 pass 声明它使哪些分析失效，不能沿用旧的证明。

## 从 HIR 构造

输入是已经完成宏展开、绑定解析和声明处理的 HIR。构造按求值顺序把树变成块和边：

- 局部变量的读写变成 SSA；被闭包捕获且被赋值的绑定变成抽象 cell 操作，cell 怎么存由表示选择决定。
- `block`/`return-from`、`tagbody`/`go` 在同一函数内变成边，途经的动态范围在边上显式离开；跨函数的退出保留退出点和令牌。
- 可能退出的调用有正常边和退出边，结果只在正常边上可用。`catch`、`unwind-protect`、special 绑定、`progv` 变成带区域的操作；`unwind-protect` 的 cleanup 覆盖正常和非局部两种离开方式，cleanup 自己的退出覆盖原来的退出。
- 多值用显式的 bundle：取主值、转发全部值、保存和恢复分别表示，个数固定时拆成普通值。
- 局部函数组保留相互递归和捕获身份；已知调用引用函数编号。
- 声明引入的检查和位置作为检查义务保留，后续表示变化不能遗漏它们。

## 分析

- 可达性、支配关系、use-def、循环和调用图；递归组按 SCC 求摘要。
- 类型和整数区间传播：固定点迭代、widening，预算耗尽时回退到保守事实。CL 类型的含义通过既有类型系统判断；数据流事实仍需要区间、合流和 widening 等分析域，类型查询返回未知时保守回退。
- 局部调用身份、参数和多值返回的摘要，lambda lifting，按策略和增长预算的内联。
- 别名、对象包含关系、捕获和逃逸，用于 cons、闭包、rest 列表的存储选择。
- 装箱消除、整数和浮点机器值、运行期检查和显式慢路径。

效果摘要分别记录堆和全局的读写、动态环境访问、分配、GC、可能退出和未知调用。结果没被使用不能证明操作可以删除；删除分配还要证明身份、错误和调试器能观察到的行为不变。未知调用、不透明类型和动态退出扩大效果和逃逸集合。

活 image 里的全局函数可以重定义：调用全局函数默认读函数 cell；直接调用、内联和布局特化需要语言保证（CL 函数不能重定义）、守卫或依赖记录（[dependencies.md](dependencies.md)、[specialization.md](specialization.md)）。守卫失败走显式的普通路径。seal 后才使用冻结世界的更强证明。

## 类型驱动的改写

MIR 在 Lisp 里，所以类型推导之后可以生成 Lisp 形式再拼回来：改写函数拿到调用点的实参类型，返回一个 lambda 形式，经 HIR 转换（在定义环境里，带依赖记录）、构造成 MIR 子图，替换原调用，然后让受影响的分析失效。这是 SBCL deftransform 的做法，适合 `append`、序列函数、`typep`、CLOS 调用点特化这类改写（现在在降级时手写，见 [lowering.md](lowering.md) 的“降级时的改写”）。编译器宏照旧在 HIR 转换时展开，此时没有类型信息。

## 身份和存储的证明

- 标量替换要求对象身份不可观察，字段别名和写入都已纳入分析。
- 保留身份的栈存储要求对象及其可以到达的引用不越过本帧或动态范围；未知调用、返回、全局存储、堆容器和捕获都可能逃逸。rest 尾部、对象字段和闭包捕获要传递地检查。
- 循环重入、对象比较、可变字段和调试器观察必须参与证明；不能让一个分配点的多个身份同时存活在同一个栈槽里。堆对象不能指向栈对象。
- 无法证明时保留堆分配和装箱。`dynamic-extent` 声明也走同一套证明。

证明的结论在 LIR 里表现为 `stack` 存储和 `word`/`f64` 变量，Rust 信任它们（[lir.md](lir.md) 的“原则”）。

## 参数绑定

参数数量、optional/key 初始化、supplied-p、rest 及声明检查由 Lisp 转成普通控制流，默认式的副作用与退出参与同一分析。LIR 只保留参数计数、实参读取和 rest 构造操作；Rust 根据 ABI 实现这些操作。

## 表示选择和输出

表示选择决定每个值是 `obj`、`word` 还是 `f64`，插入装箱和拆箱；决定 cons、闭包、cell、rest 列表的存储；完成闭包转换（捕获什么、内部入口的捕获项前缀）；把个数固定的多值拆开。然后退出 SSA，块参数改成边上的并行复制，拆分临界边并用临时量解决复制环，输出 LIR。

## 验证

构造之后、结构改写之后、输出 LIR 之前运行验证器：编号、SSA 支配、边的实参、终结指令、捕获关系、多值协议、区域嵌套、调用签名和策略来源。验证失败是编译器内部错误，不发布部分代码。

## 和 HIR 求值器的关系

HIR 求值器（[hir.md](hir.md) 的“编译期求值”）照旧直接在 HIR 上构造闭包，不经过 MIR。两者共用绑定、参数协议、声明和退出的语义。

# MIR：Lisp 语义中端

MIR 是默认的原生编译中端。它从 HIR 构造 CFG，验证 SSA，完成语义分析与表示选择，再输出 LIR。HIR 求值器继续直接执行 HIR。分层与扩展边界见 [compiler.md](compiler.md)。

MIR（mid-level IR）由 Lisp 从 HIR 构造，是控制流图加 SSA。它负责 Lisp 程序的分析、优化和表示选择，最后退出 SSA，输出 [LIR](lir.md)。MIR 不是通用的低级 SSA：对象身份、闭包、可写捕获、多值和动态范围在 MIR 里仍是可辨认的操作。机器层的通用优化留给 Cranelift。

## 当前框架与入口

树上的绑定读写不能直接作为 SSA 使用，循环回边和条件合流必须给每条进入边
提供变量的当前版本。构造器为每个函数单独编号绑定，用临时引用连接完整的
词法状态；需要表达式结果的合流块另带多值 bundle 参数。图完成后，从实际
用途沿入边反向追踪，只为需要的绑定物化 SSA 参数，并同步压紧入边实参。
回边和交换赋值使用同一规则，临时引用不会离开构造阶段。后续 SSA 变换只
要求参数与入边实参的数量和表示匹配。

仍有用途但未改变的绑定会在合流点和回边上重复传递。`mir-simplify-block-parameters`
在表示选择前消除这些冗余参数：若所有可达入边在忽略自身回传后都提供同一个值，
且该值的定义支配当前块，就用它替换参数；交换赋值及不同来源的合流继续保留参数。
随后从指令和终结点的实际操作数反向追踪用途，只有目标参数被使用时才追踪对应
边实参，删除仅在边上循环转发的无用状态。指令、副作用和声明检查保持原样。
改写同步收缩所有入边，重新连续编号 SSA 值，并通过 pass 接口失效分析、验证
支配关系及函数和捕获布局。cell 句柄和多值 bundle 按原表示处理。

支配分析按逆后序计算立即支配者，并用支配树中的区间判断一个块是否支配另一个块。
函数体改写声明控制流不变时，验证可复用支配树，仍检查 SSA 的定义与使用关系。
显式验证重新读取控制流。没有分配候选的函数在降级时跳过存储分析；
单函数单元没有内部调用边时，类型和多值事实直接使用局部分析。

实现分为 `lisp/mir/data.lisp`、`verify.lisp`、`build.lisp`、`lower.lisp`、
`values.lisp`、`types.lisp`、`calls.lisp`、`escape.lisp`、`predicates.lisp`、`lifting.lisp`、`scalar.lisp`、`simplify.lisp` 和 `dump.lisp`。编号索引复用可增长向量容器，语义值表示为 `obj`、`bundle`、参数计数 `count` 和内部 cell 句柄 `cell`。返回个数已知为 1 的 bundle 直接保存对象；需要保留次值的其他 bundle 使用
保存载体和个数，跨调用后恢复，避免借用的多值区被后续调用覆盖。

只读取主值或返回个数时，保存全部次值会构造一个随后无人读取的载体。
多值计划区分完整值组的需求与跨覆盖保存的需求：从次值读取、多值调用、返回
和非局部退出反向传播完整需求，主值读取和存在性测试只要求主值与个数。
仅有这些用途的 bundle 使用普通局部量，跨调用及 GC 后仍可读取主值和个数。

完整返回也不必立即分配载体。若生产者到返回点之间的路径保留 ABI 多值区，
主值、个数与借用视图可以成对穿过合流点。`mir-return-value-owners` 在 CFG 上
追踪仍对应当前多值区的 bundle，合流取所有前驱都成立的事实，重新赋值的块
参数先撤回旧身份，再映射入边的身份。调用、分配、检查、动态区域、循环 poll
以及可能恢复其他值组的转换撤回证明；目前多 bundle 的合流也保守保存。

载体保存本身可能使旧借用失效，因此计划增加一个载体后会重算路径证明，直到
不再需要新增载体。已证明安全的完整返回使用 `move-values` 成对转发主值与计数，
规范化为 LIR 的 `mv-move`，由 Rust 按 CFG 验证借用的有效性。边上的视图先移动到
独立结果对，再更新目标参数，避免并行复制环破坏来源；这些移动不分配堆载体。
借用结果对保留计数变量以标识对应视图，其他已知个数可直接使用常量。

不能保持次值的路径继续保存私有载体，并在需要时恢复。合流或声明检查的输出
可能只需要主值，而输入因其他用途保存了完整载体，此时提取主值与个数，不能
把载体指针当作主值。单值对象进入完整用途时可直接建立单值视图；其他来源的
完整需求必须反向传播到生产者。

已支持常量、局部绑定与赋值、全局变量和函数 cell、词法闭包及局部函数组、普通调用、
原语调用、`if`、顺序形式、`block`/`return-from` 与 `tagbody`/`go` 的函数内及跨函数退出、
`multiple-value-prog1`、`multiple-value-call`、词法和 special `multiple-value-bind`，以及主值类型检查。
局部作用域和函数参数支持 special 绑定。函数入口支持必需与可选位置参数、`&rest` 与 `&key`，并检查参数数量范围。
函数含有 `&key` 时，入口调用共享解析器，遍历实参后缀一次并保存各键的首个值与
是否提供。这样默认式即使修改 `&rest` 列表，后续关键字绑定仍使用进入函数时的值。
参数默认式与声明检查继续按源码顺序执行。解析器的快照需要临时向量，函数体的
控制流只包含各键的绑定和默认式。

只需要主值时，构造器直接生成单值对象，顺序形式及词法绑定把需求传给结果表达式，
条件分支也直接合并对象。确实需要值组的上下文仍可包装
成单值 bundle，降级时可以和对象共用局部量。无条件跳转在源块内完成平行复制。
条件边仅在有活跃且不同的目标参数时使用中间块，异常落点保留专用入口。
语义 SSA 仍记录 Lisp 对象与多值；降级时另选机器值表示。已知所有参数都是
double-float 的二元及多元加减乘除和一元取负、绝对值、增减直接使用 `f64` 运算。
六种二元数值比较及 `zerop`、`plusp`、`minusp` 也直接消费原始浮点值；
混合类型比较仍保留通用调用，避免把大整数转换为浮点数后误判相等。
一元谓词与整数零比较时，非有限值沿用运行期混合数值比较的结果。
省略类型检查和选择机器值表示仅依赖 MIR 类型事实，并遵守优化策略和 `notinline`。
`expt` 的底数已知为正的二次幂时，MIR 对结果能用 fixnum 表示的非负
fixnum 指数使用移位。已知指数区间落在该范围内时直接移位，否则先检查，
超范围或采用其他表示的指数交给普通 `expt`。
原子 `signed-byte` 与 `unsigned-byte` 的常量测试直接检查整数种类；后者再检查
非负性。整数种类包含 bignum，比较的大整数回退仍参与判断，不能只用 fixnum tag
替代这两个无位宽限制的类型。若合取中的其他约束将值限定在 fixnum 区间内，
编译器合并各项边界。例如 `DOTIMES` 的非负声明与显式 `fixnum` 声明合并后，
共享声明检查只需测试 fixnum 种类及符号，后续运算也能使用该区间。
不能证明类型时使用通用实现；共享原语可以保留运行期类型守卫及完整慢路径。

单精度与双精度算术共用一套快慢路径。降级先检查动态浮点控制状态，
在默认模式下发射硬件运算，遇到非有限结果时交给运行时按当前语义处理。
精度决定机器运算、非有限值的位检查和慢路径的装箱方式。
双精度在 LIR 中用一个分类操作表达。后端只检查指数位，因此检查信令 NaN
时不会触发浮点异常。x86 目标支持 SSE4.1 时，后端用 SIMD 位测试直接检查
浮点寄存器中的结果，省去把结果移入通用寄存器和提取指数的指令。
单精度的非有限值检查读取结果的指数位。只供其他单精度算术使用的中间值
可保存在 `f32` 局部变量中。对含有单精度类型事实的函数，降级检查指令及控制流边
上的使用，沿主值和已证明的声明复制追踪来源。普通调用、对象操作、调试观察和
控制流边参数要求对象表示。软件回退在调用前给
未装箱实参加标签，返回后按结果的使用方式保留对象或解码。发射同一 MIR 块时，
重复使用的带标签操作数只解码一次。特化单精度数组只供算术使用的读取结果
也可直接进入 `f32` 局部变量。通过原有布局与边界检查后，后端读取元素的
binary32 位。慢路径返回带标签值，降级器随后解码。
多元双精度调用作为一条算术链降级，按顺序折叠。入口检查一次控制状态。
硬件运算得到有限结果后直接进入下一步的硬件块。慢路径返回后若还有下一步，
则重读状态再选择路径，因为调用期间执行的 Lisp 代码可能改变它。
循环内未装箱的双精度乘积若直接加到一个已证明可直接读取的数组元素上，
默认模式可以先完成乘法、读取和加法，只检查和是否有限。非有限乘积参与加法后
仍是非有限值，因此检查能覆盖两次运算。和非有限或启用了浮点控制时，按源码
顺序执行原有检查和回退，使乘法上的条件先于加法报告。两次硬件运算各自舍入。
如果乘数刚由非零 fixnum 转成双精度并求倒数，发射器还可把输入数组的边界检查
与浮点模式检查并在一个守卫中。默认模式下，倒数有限且不会触发条件，通过守卫后
可以先读取输入元素，再连续执行转换、除法、乘法和加法。任一守卫失败或最终和
非有限时，慢路径按原顺序求值。两次数组读取都使用已知的存储，累加目标的
下标已证明合法。这项匹配只查看同一 MIR 块中紧接的指令。

当这个算术链的结果立即写回同一个数组元素，且该元素在循环入口就已证明可读时，
发射器可以复制循环并将元素保存在一个未装箱的累加值中。计划复用自然循环和
下标证明，要求目标数组与下标在循环内不变。入口比较两个后备存储，同一存储
进入原循环，因为输入读取可能看见此前的写入。循环副本只能包含匹配的两次读
和一次写，发射后还会检查每条回边恰好完成一次更新，且失败分支出现在更新前。

每轮从 `poll-branch` 进入无调用的循环体。收到 poll 请求时，先把已完成的
累加值写回，再处理请求并从当前迭代继续执行原循环。边界、溢出或浮点守卫
失败时，先写回已有结果，再让原循环执行当前迭代并报告相应条件。正常退出
也会写回。每个函数最多复制一个循环，复用常规循环复制的块数与指令数预算。

同一循环块内的双精度整数转换可以复用已有状态，或在紧接双精度运算时建立缓存。
默认模式直接使用硬件转换。
如果非零 fixnum 的转换需要检查舍入模式，且结果经主值投影后立即用于求倒数，
且转换处无需装箱，默认路径可在一次模式检查后连续完成转换和除法。
软件路径仍按原顺序转换、读取转换后的控制状态并求倒数。
启用浮点控制时，能精确表示的整数仍用硬件转换，其余整数交给运行时按当前
模式舍入。转换的慢路径返回后重读状态，供同一块内后续的浮点运算使用。
浮点控制宏在展开时验证字面参数，展开后的代码在运行时建立动态绑定。
宿主交叉编译和原生编译因此可以使用同一宏定义。
循环内的单精度和双精度算术可在同一个 MIR 块内复用控制状态判断。常量、值转发和
已证明的声明检查保留缓存。使用已读取的后备存储访问特化数组时，直接读写
也保留缓存。算术或访问的回退调用返回后，重新读取状态。其他指令或后备
存储查询使缓存失效。缓存只保存机器字布尔值。

只在每次算术调用内拆箱，会使算术链和循环在相邻操作之间反复分配 double 对象。
各指令都允许优化时，降级为已证明的 double 对象值和
恰好返回一个 double 的 bundle 建立 `f64` 变量。赋值、主值读取、已证明的声明检查
及块参数传递原始位。边复制先计算可能转换表示的来源，再按复制依赖更新目标，
仅复制环需要额外临时变量；这也保护循环回边和交换赋值尚未读取的来源。
纯复制链和块参数先按使用关系求活跃性，避免未使用的绑定状态迫使中间值装箱。

返回、普通调用、捕获、cell 写入、对象操作及混合类型合流需要对象表示。
降级从这些使用反向传播对象需求，沿复制链和边要求对应来源保留对象。
算术结果仅在需要时于原指令位置装箱；同一值的对象使用共享这份对象，
后续算术仍可读取其 `f64` 变量。来自参数、调用或检查的对象在完成原操作后
读取原始位，未证明的声明检查先执行再拆箱。调用边界和多个返回值的保存载体
继续使用对象；高调试策略下，源码变量的调试观察和可写绑定的 cell 仍要求对象，
只供算术使用的 SSA 临时值可以保留原始位。此时沿复制链标记被观察的算术来源，
参数、合流参数及其他非算术来源仍保留对象，使源码变量在调用点继续保持对象活跃性。
`f64` 变量不包含 GC 指针，跨 poll 和调用
保持原始位，仍有对象用途的副本按普通对象变量进入精确栈图。
fixnum 的声明检查可能从一个仍需追踪的对象输入得到立即数。通过检查后，
降级把结果以 fixnum 的标记位表示交给 LIR，后端据此从 GC 根集合中省去该值
及其复制。声明检查失败时，用原对象构造类型错误。这条冷边通过条件系统离开，
成功路径直接使用检查后的值。
如果循环参数的对象用途只有普通返回，运算产生的双精度值可以到返回时再装箱。
循环边传递原始位和一个对象槽。已有对象继续沿边传递，新产生的原始值将对象槽置为
NIL。返回时复用已有对象，或按原始位装箱一次。这样零次迭代仍可返回原对象。
如果中途需要读取对象或源码变量需要完整调试观察，仍在原位置装箱。
非零 fixnum 转为 double 后的绝对值至少为一，且远低于 double 的上限，
因此倒数一定是有限的正规数。输入区间不能排除零时，发射器在除法前检查除数，
并和动态浮点模式一起决定是否进入通用路径。硬件除法完成后可以直接使用结果。
两个由 fixnum 转换而来的双精度操作数做加、减或乘时，结果也一定有限。
发射器省去硬件路径上的结果检查，仍按动态浮点模式选择运算路径。
fixnum 运算保持带标记的对象表示。MIR 证明操作数都是 fixnum 后，二元加减乘、
按位与或异或、六种比较，以及 `1+`、`1-`、`zerop`、`plusp`、`minusp` 可直接降级。
当 `ash` 的移位量已知且非正时，MIR 移动输入区间的两个端点以推导结果，
后端直接右移带标签的输入，再将最低位置零。超过机器字宽的移位只保留符号，
因此发射时将计数限制在 63。单参数减法用零减去 fixnum，区间证明可排除溢出；
最小 fixnum 仍通过通用路径产生任意精度整数。
这些选择同样遵守优化策略和 `notinline`。类型未知或仅知为 integer 时，
共享算术原语保留 fixnum 类型守卫、溢出检查及通用数值慢路径。
同一 MIR 块内的分支直接使用已特化的 fixnum 比较结果。分支条件中的可内联
`not` 和 `null` 只改变分支方向。比较值仍可供其他指令读取为 Lisp 布尔值，
后端可以省去只供分支使用的对象表示。
比较一侧为 `(ash n -1)` 时，`i <= (ash n -1)` 及其交换操作数的形式
可直接把原 fixnum 交给后端比较，省去比较操作数的重新加标签。
当除数是二，且 MIR 已证明 fixnum 被除数为偶数时，直接右移带标签字即可
得到商。需要第二个值时发布零余数。
比较 fixnum 和整数时，相等性可直接比较对象字。若区间证明较宽的操作数只可能
在 fixnum 范围的一侧成为 bignum，顺序比较在检查标签后即可确定该侧的结果。
`evenp` 和 `oddp` 对已证明的 fixnum 直接测试低位。循环内和偏向运行速度的
调用也可在测试对象类型后走同一条路径，其他对象交给通用函数。
操作数能放入 fixnum 时，加减乘根据结果区间决定是否检查溢出。双方的安全级别
均为零时，紧接在算术结果后的 fixnum 声明也能约束结果，发射器据此使用机器
算术。需要检查声明的路径在溢出后调用任意精度数值操作，声明检查仍看到完整结果。
如果算术链的叶子都是 fixnum，而且中间值只流向带固定非负 fixnum 掩码的
`logand`，发射器可用机器字完成加减乘。掩码只保留截断前后相同的低位。
返回、其他读取或调试观察仍需要完整整数，因此有这些用途的中间值按原规则生成。
循环里的双下标 `aref` 可以内联访问登记过的非位数组布局。守卫确认数组没有位移、
秩为二、两个下标分别在维度内，并检查存入值符合元素类型。由这些事实可直接计算
行主序下标并访问后备向量。任一检查失败时调用通用入口，沿用原有错误处理和位移语义。

一段从零递增的行循环如果只读取两个同列无符号整数、求和并写入第三个数组，
可以在行入口验证三个数组的布局和下标范围，并为每个后备向量计算行起点。
两个源元素类型的上限之和能放入 fixnum。若目标上限不小于这个和，行循环可以直接
存入结果。其他情况在每次写入前检查结果，失败时从原循环的当前列继续，保留
先前列的写入。快循环每轮检查 poll 标志，
有待处理的运行期工作时先恢复原循环的列下标，再进入 safepoint 并回到原循环。
若列下标保存在可变词法 cell，只有 cell 的所有用途均为当前函数内的直接读写时，
发射器才把下标保存在寄存器中，并在正常退出和回退时写回。
快循环按四列展开，摊薄回边的寄存器搬运和 poll 开销。末尾不足四列时逐列执行。

反向交换数组元素时，循环常用 `(<= i (ash z -1))` 控制正向索引
`i`，再用 `(- z i)` 访问另一端。如果通往循环体的每条边都通过该比较，
且只把零或上轮索引加一传入循环体，MIR 可证明 `0 <= i <= z`。
当 `z` 是 fixnum 时，同一循环体中的差也是非负 fixnum。右移一位还将 `i`
限制在 fixnum 上限的一半以内，因此用这个索引加一时无需检查溢出。
如果进入循环体前还证明了
`z` 小于该数组的长度，MIR 可将同一个边界证明用于两端的访问。
如果短循环有唯一外部入口，并且多次访问同一个长度固定的特化向量，
发射器可在循环入口将 `z` 与缓存的长度作无符号比较。通过检查的路径使用
省去逐元素检查的循环副本。检查失败时进入原循环，按源码顺序执行访问及错误处理。
零起点循环通过长度守卫后，初始的 `(<= 0 (ash z -1))` 必定成立。如果这条
入口路径只计算比较和局部值，且没有 poll 或供外部读取的结果，发射器可提前检查
长度，直接以零下标进入快速副本。
对只交换同一 fixnum 向量两端元素的循环，通过长度守卫后，下一轮仅在
正向下标严格小于反向下标时执行。两者相等时，两次写入都会还原同一个元素，
而循环结果只通过向量对外可见，因此可以省去中点自交换。
两个副本都按原循环控制流保留 poll，发射器为代码增长限制每个函数复制的循环数量及大小。
更短的快速循环可以展开两次。第二次迭代只在原条件允许时执行，展开后的回边
仍回到第一次迭代的 poll。
紧凑的反转循环可在同一个入口守卫之后先执行最多五次迭代。每次仍按原条件
退出，剩余迭代进入带 poll 的循环。前缀中原来返回循环入口的边通向下一份副本，
副本内部的循环继续经过原有 poll。
短向量复制可展开有限前缀。下标从一开始且每个回边都加一时，只要已证明
下标在目标向量内，减一后的下标也可直接用于相邻位置的写入。同一次证明
还可用来消除自增的溢出检查，因为下标加一最多等于向量长度。
发射器要求源向量和目标向量都已有边界证明，按循环体的 MIR 指令数限制副本数，
每个函数最多展开两个独立的复制循环。每个副本保持加载、写入和退出判断的顺序，
所以源向量和目标向量可以共享存储。剩余迭代从原循环的入口 poll 继续。
MIR 将结果范围证明传给公共 LIR 算术发射器。对紧接一元或二元 fixnum 算术的
`fixnum` 声明检查，发射器把检查并入运算的溢出分支。未溢出的结果已知是
fixnum；溢出时先计算完整整数，再用它作为类型错误的 datum。该错误路径可经
原有条件处理器展开，正常控制流从未溢出的分支继续。
三个或更多 fixnum 相加时，MIR 合并各操作数的区间。如果最终和能用 fixnum 表示，带标记的模加法直接得到正确结果。范围不足时，每一步检查溢出，任一步溢出都把原实参交给通用加法。实参在进入算术路径前已经按源顺序求值。

一元和二元除法在没有更具体的机器路径时可直接走 kernel 的固定参数入口。
一元形式传入整数一作为分子；更长的调用由可变参数入口按顺序处理。

容器访问需要分别证明表示与索引是否合法。已知 simple-vector 的 `aref`、`svref`、
`elt` 及对应写入可省去对象种类检查。索引的 MIR 类型已证明为 fixnum 时省去
整数种类检查，区间下界非负时也省去负数检查；索引小于长度的检查仍然保留。
已知原生字符串的 `char`、`schar`、`aref`、`elt` 可省去对象种类检查，仍检查
索引为非负 fixnum 且小于长度；写入还检查值是字符。
所有实参先按源程序顺序求值，再执行访问检查；索引错误也不会跳过写入值的求值。
失败分支把原参数传给运行期访问器，由后者报告索引或值的错误。
已知 simple-vector 或原生字符串的 `length` 直接读取表示中的长度。
一维 simple-array 的 `elt` 可使用现有数组访问分派，其他表示继续由运行期处理。

单下标 `aref` 及其写入即使没有对象类型证明，也使用带种类检查的数组访问分派。
原生向量和字符串通过索引检查后直接访问，其他对象交给单下标运行期访问器，
避免进入通用的下标列表和行主序索引计算。二下标和三下标调用将固定数量的下标
交给运行期，运行期核对布局并逐维计算索引，其他表示交回通用访问器。其余
下标数、`notinline` 和低优化策略使用普通调用。

特化简单数组的降级计划为每个可共享的访问记下后备存储的来源，并按访问次数
决定哪些来源值得提前读取。发射访问时直接用这份映射，声明检查和复制链只在
制定计划时追溯。映射按候选访问增长，仅在本次函数降级中使用。
成功执行带检查的访问后，降级器记录索引 SSA 来源和简单数组来源。
对于已知长度的向量，证明也可用于长度至少相同的向量。证明使用 MIR 值编号
和静态长度，后备存储及长度对应的 LIR 变量只用于生成访问指令。
发射前沿可达控制流传播证明。已知长度时，汇合点对同一索引取所有入边上界的
最大值，因此只可省略对长度至少达到该上界的向量的检查。长度未知时，每条入边
都必须证明同一索引已通过同一数组的检查。循环回边与首次进入循环的边按同一
规则处理，直到块入口的证明稳定。进入定义索引或数组值的块时，
丢弃涉及这些值的旧证明，防止把上一轮迭代的检查用于新值。证明只沿普通控制流
传播。常量下标按数值共享证明，同一个字面量在不同块产生的 SSA 定义也可复用
已经完成的检查。
扫描只对计划了共享后备存储的函数执行，工作表随块和候选证明增长。

循环的退出条件也能为第一次访问提供证明。简单特化向量由 `make-array`
构造，且长度取自函数入口的 SSA 值时，降级计划记录向量与该长度的关系。
构造点支配比较所在的块，且比较已排除索引达到长度的分支时，非负整数索引
可沿继续执行的边获得边界证明。证明沿用访问检查的传播及失效规则。
已在入口取得后备存储的简单特化向量，也可以用同一向量的 `length` 建立
边界证明。已知维度的 `length` 直接发射常量，动态维度复用后备存储的长度。
简单特化数组的秩未声明时，`length` 仍执行原有检查。调用正常返回后，结果是
向量的长度，循环可以沿下标小于该长度的边复用这个证明。
循环上界是两个 fixnum 的 `min` 时，下标低于该上界也就低于两个输入。
发射器沿这一层关系复用输入中已有的数组长度证明。
当比较的成立边证明长度至少为一时，首元素访问也可直接使用后备存储。
反转循环使用 `(ash (1- z) -1)` 跳过中点时，成立边仍能证明正向和反向下标
都介于零和 `z`。这类循环保留首次比较，以允许空区间直接退出。
若同一个 SSA 值同时是该向量的长度下界，正值减一后也在向量内。对已知的
fixnum 下界，减一无需检查溢出。控制流汇合时，每条到达边都必须证明该值为正。
向量构造可为私有入口建立长度上界。每个普通调用须传入向量及其实际长度，
自递归调用须原样转传向量，长度参数可原样转传或减一。循环也可以用
`i <= (- length 1)` 的继续边提供上界，覆盖在回边前更新下标的循环。
自递归私有入口每次都需要取得向量参数的后备存储。降级可直接按实例的 stamp
查找已登记的槽，省去调用数组访问器的开销。快路径与运行期访问器共享查表代码，
找不到已登记布局时调用访问器，由它完成普通的槽访问。

普通 string、simple-string 和 vector 声明不保证原生对象布局，因而不足以直接读取
这些字段。`:make-simple-vector`、`:make-string` 原语则明确产生对应原生对象并返回
一个值；这些事实由 MIR 重新生成并跨 SSA 和调用摘要传播。标准容器 setter 的
单值结果是所写入的值，类型与多值摘要均使用这一契约。表示未知时，共享原语
保留对象种类检查及通用慢路径；`notinline` 和低优化策略保留通用调用。

`find` 和 `position` 的实参已证明是简单向量，且调用使用完整范围、默认键函数
及固定的 EQ 或 EQL 测试时，可直接发射扫描循环。常量 `:from-end` 决定扫描
方向。反向扫描从长度开始，把下标减一再取元素，因而空向量直接返回 NIL。
入口读取一次长度，循环
用未装箱下标读取元素。待查值已证明为 fixnum 时，EQL 可以比较对象字，无需生成
堆数值慢路径。其他 EQL 搜索仍可调用通用数值比较。速度优先的对象字比较
每批先确认还剩至少四个元素，再按扫描方向比较，命中后立即退出。末尾不足四个
元素时逐个扫描。每批保留一个 poll，尾段和堆数值搜索逐元素 poll。

`member` 和 `assoc` 的通用入口需要解析关键字并调用测试函数。MIR 根据 SSA
定义识别没有关键字的默认 EQL 调用，以及仅含常量 `:test` 和 EQ／EQL 函数设计符
的调用，将它们改为两参数搜索 helper。参数的求值指令留在原处，因而测试函数
表达式中的副作用仍按原顺序发生；其他关键字、动态测试和 `notinline` 保留通用入口。

EQL 与已知常量比较时，若该常量不需要堆数值比较，就改用 EQ；大整数、比值、
双精度和复数仍保留 EQL。APPEND 去除非末尾的已知 NIL 参数，零个参数返回 NIL，
单个参数直接返回原对象，两个参数调用固定入口。末尾 NIL 必须保留，因为它要求
复制前面的列表；这些改写只改变调用操作数，参数求值与声明检查仍留在原处。

常量槽名和构造器关键字也从 SSA 定义取得。槽读写共用按类 stamp 校验的位置缓存；
构造器共用按类与初始化协议假设校验的目标缓存，失效时重新选择目标。所有实参先
求值，再访问缓存。动态名称、未能确定的关键字和 `notinline` 保留普通调用；kernel
与 CLOS 模块内的构造调用使用通用入口，避免构造协议依赖自身的缓存入口。两条 IR
路径共用缓存发射器和运行期守卫，缓存中的对象引用通过静态 root 保持 GC 可见。
槽读取将 `slot-unbound` 的结果归一为一个主值，零值时返回 NIL；缓存命中和回退
路径遵守同一契约。

类型谓词的结果已知后，仍只在 LIR 发射时折叠，会让 MIR 的后续分析继续把
原调用当作对象使用。`predicates.lisp` 根据 MIR 类型事实，把可证明真假的具名
一元类型谓词改为布尔常量和单值构造；原有实参求值指令保留，包含错误和回调的
实参仍按原顺序执行。NIL 同时属于 symbol 和 list，因此仅凭其中一种宽类型
不能把另一类谓词折叠为假。未知类型的原语谓词保留运行期类型判断；
`notinline` 及低优化策略保留调用。

改写通过 pass 接口推进函数版本、失效分析缓存并验证 SSA。局部函数返回类型
可能随常量结果变得更精确，调用方可以据此折叠更多谓词。
条件的两条边若继续保留，不可执行的分支仍会扩大返回类型和逃逸集合。因此同一
迭代还根据测试值的 MIR 类型或其常量定义选择已证明的后继，把条件终结点改成
单边跳转。原测试的求值和声明检查保留；symbol 和 list 都可能包含 NIL，不能
仅凭这些宽类型选择真分支。每次改写失效可达性及单元摘要，直到谓词和条件边都
不再变化。低优化策略保留条件边。

随后运行标量替换，使只供已折叠谓词使用的 cons 也能消除存储，同时保留其字段
表达式的副作用。这个顺序让类型结论参与后续存储证明，而不只是减少运行期调用。

类型声明重新生成检查，再由 MIR 的类型事实证明是否可以省略；
HIR 的区间、逃逸、栈存储和拆箱证明不导入 MIR。
公共准备阶段若先合并函数或改写调用，MIR 建图时就失去了原来的函数边界，
也无法独立决定这些优化。因此前端只准备绑定、捕获、声明和退出等公共信息；
函数别名与身份传播、内联、短列表展开、类型推导、调用特化、cons 标量替换
和闭包存储选择均由 MIR 在自己的定义和控制流上完成。嵌套编译使用独立请求
和 MIR 单元，不将另一份编译的优化状态写回共享 HIR。
指令和终结点保留源码位置与策略，调用还保留 `notinline` 约束。

MIR 将嵌套函数平铺到单元的函数表，发射器的当前函数名因而不足以恢复词法
上下文。构造器在平铺前计算函数的 `debug-name`，保留全局定义名、局部函数名
及匿名函数的词法父函数。LIR 发射直接使用这份元数据。

交叉编译和原生编译均默认使用 `debug 1`，为局部优化保留 SSA 表示，并记录函数名
和源码位置。需要从调试帧观察源码绑定时，可用 `(declare (optimize (debug 2)))`
或 `debug 3`，也可以用全局 `proclaim` 设置调试级别。

一个可写绑定的多个 SSA 版本可能同时存活，例如另一个变量仍保存赋值前的值。
把这些版本都标成同一个调试变量，会同时暴露新旧值。因此源码策略达到
`debug 2` 的可写绑定使用 cell，赋值更新其内容；只读绑定仍使用普通 SSA 值。
构造器在绑定、赋值和捕获入口生成 `debug-binding`，记录绑定编号、源码名字及
当前对象或 cell 句柄。这些额外 cell 是保留可写调试绑定的存储成本。
可选参数和关键字参数的实参与默认值在入口 CFG 中合流，合流后的块参数另行
登记变量名，使调试信息直接描述函数体实际使用的值。

`debug-binding` 是显式的 SSA 使用，验证器检查绑定编号、名字及对象／cell 表示，
并拒绝观察未初始化的 cell。调用与逃逸分析将调试观察视为公开用途，含调试绑定
的函数体保留独立调用帧。发射器复用 LIR 的变量标签及 cell 描述，不改变运行期
调试协议。只有调用点仍有栈槽的值才会出现在帧变量中；宏引入的隐藏变量不生成
源码绑定记录。模型检查见 `tools/test-mir-debug.lisp`，运行期检查见
`tests/m6/co-mir-debug.lisp`。

类型测试的实参先按 MIR 指令顺序求值，再选择测试方式。两参数 `typep` 的类型
若能沿 SSA 定义追溯到常量，就复用内联类型测试或类型缓存发射器；动态类型、
显式环境参数、`notinline` 和不允许优化的调用保留普通调用。前端在转换时展开
字面量类型和声明中的类型别名；已有匿名函数保留该展开结果，具名定义通过依赖
追踪重新编译。声明检查失败时仍报告原声明。整数区间等标准类型直接比较；
其他满足缓存条件的常量类型使用可写的调用点缓存。

类型和类定义可能改变，所以缓存每次使用前检查对象的类 stamp 和类型假设
版本。值相关的 deftype 与 `satisfies` 由运行期判定为不可缓存，继续逐次执行
实际测试。MIR 只提供常量与类型证明，缓存布局和版本规则与 HIR 共用，不读取
HIR 节点上的推导标记。代码生成选择测试见 `tools/test-mir-type-tests.lisp`。

生产路径的切换仍按 [compiler.md](compiler.md) 的语义与性能门槛进行。

`the` 的 `values` 声明检查各位置的类型，同时保留生产者原来的值和个数。
必需位置缺失时按 NIL 检查，可选位置只检查实际存在的值，`&rest` 遍历余下的
实际值；未声明的位置不加检查。这与 [THE 的返回约定](https://www.lispworks.com/documentation/HyperSpec/Body/s_the.htm)
一致，不能用声明长度替代实际计数。

构造器先保留原 bundle，再用固定位置读取、存在性分支和 rest 游标循环执行
检查。每个检查沿用主值声明的类型错误接口，错误携带实际值和对应的源类型。
检查中调用 `typep` 或 `satisfies` 会覆盖多值区，因此后续读取与最终返回始终
依靠已保存的载体。rest 游标从私有值列表的尾部读取，单值表示先建立一个临时
列表；这个堆存储边界参与逃逸分析，防止载体包含栈对象。

检查完成后，透明的 bundle 注解细化多值类型摘要，不改变精确个数或未知计数。
必需位置可按检查结果细化；计数未知时，可选及 rest 位置还须保留缺失 NIL 的
可能性。已知计数也可折叠存在性分支。类型前缀仍受摘要预算限制，运行期检查
则覆盖声明涉及的全部实际值，不能因为前缀截断而漏掉后面的错误。
组件中的类型别名在词法环境中展开，已展开的检查与证明保留同一份定义。

带签名的 `function` 是声明类型，不能直接交给 `typep`。声明检查把它投影为
可判定的函数类别；布尔组合及结构组件保留不会拒绝合法值的检查条件，无法
判定的否定条件保守放宽。参数和返回签名仍是程序的声明，检查不包装函数，也
不改变对象身份。声明投影保留在公共类型工具中，多值检查由 MIR 的 CFG 和
bundle 事实独立生成。

`throw` 是无正常后继的终结点，显式接收 tag 对象和多值 bundle。构造器先求出
tag 的主值，再求值结果形式；两者任一非局部退出后都不继续构造后续表达式。
降级先恢复 bundle，再沿现有展开 ABI 传递，零个值和多个值保留完整个数。
活动的 special 和 `progv` 区域留给 unwinder 恢复，不能把它们当成普通返回前
的显式离开，也不能在展开前撤销仍存活的栈根区域。

普通返回可以通过借用摘要把某个参数交还调用者，`throw` 的目标却可能位于
调用者之外，携带该参数会让调用者的帧退出。因此 tag 和结果中的对象都计入
逃逸集合，抛出的参数不能获得借用证明，抛出的函数对象计入外部可见集合。
同一规则覆盖 cons 的可达字段、闭包和共享 cell，防止展开携带已经离开的栈对象。
浮点值在抛出位置需要对象表示，沿 SSA 的装箱需求传播保证它们在展开前装箱。
tag 匹配与目标选择沿用动态环境链。

`catch` 的异常落地会绕过受保护代码的正常后继。只在进入时为词法变量传一份
SSA 快照，会丢失后续赋值：例如先 `setq` 再 `throw`，落地后仍须读到新值。
构造器因此把具有异常 landing 的函数中的可写词法绑定放入 cell；区域边传递稳定的句柄，
落地后的读取从 cell 获取最新内容。只读绑定仍用普通 SSA 值。

区域进入终结点同时列出正常后继和保守异常后继，后者代表区域内任意退出到
本目标的路径。可达性、支配关系、类型、别名和调用分析都遍历这条边，因此
正常路径上才产生的调用结果不能在 landing 中使用。异常输入保留进入前的
外层区域栈；runtime 到达时已解除本 catch 及其内层绑定。正常路径显式离开
区域后与落地结果合流。没有实际退出的区域仍保留异常后继，代价是类型和
可达性结论更保守。

验证器要求每个区域有唯一匹配的 landing，拒绝普通边进入 landing，并要求
落地取值操作位于其首部。降级在 LIR 实际标记的 landing 块中先解码并保存
多值，再执行边复制和 poll；后续分配不能覆盖尚未读取的展开载荷。每个源块
和复制边都按活动区域栈选择 handler，嵌套目标不匹配时转向外层分派。
函数级栈根区域包围 catch，所以同一帧落地后仍能使用它保护的对象。

cons 字段的标量替换目前不用于含异常区域的函数：进入时传出的字段 SSA
快照同样不能表达抛出前的字段修改。保留实际字段读写后，异常路径能看到
最新内容；普通逃逸分析和栈存储选择仍然有效。

`unwind-protect` 使用同一套区域进入与异常后继，但异常落地时条目仍在动态链上，
以“cleanup 运行中”的状态保护待传目标和值。正常保护体先保存结果、离开区域，
再执行 cleanup；cleanup 的值被丢弃，保存的 bundle 在正常后继继续使用。
局部 `return-from` 和 `go` 在离开区域时内联对应 cleanup，并按当时的绑定栈
执行它，因此 cleanup 能看到尚未离开的外层绑定与最新词法赋值。

异常 landing 执行另一份 cleanup。它的调用使用外层 handler，正常结束后通过
带区域编号的终结点继续原展开。验证器要求该区域是当前最内层且正在执行
cleanup 的条目，禁止从普通保护体直接继续展开。cleanup 若再次 `throw`、报错
或执行局部退出，新退出覆盖旧退出；局部退出只解除正在运行的条目，不会再次
执行同一 cleanup。内层 catch 若处理了 cleanup 中的临时退出，则 cleanup 仍可
正常完成并继续原展开。待传值一直由动态条目作为 GC root 保存，cleanup 内的
调用和 poll 不会丢失它。

跨函数 `return-from` 和 `go` 使用退出点区域。每次进入需要此能力的 `block`
或 `tagbody` 时分配新的堆令牌，并通过词法捕获或提升后的私有参数传给退出
函数。退出终结点显式接收令牌与 bundle，沿已有 `exit-to` 展开路径传递。
它与 `throw` 使用相同的逃逸边界，不能把可能离开调用者帧的参数当作借用。
闭包保存的是对象身份，而不是退出条目的栈地址；旧激活留下的闭包因此不能
误匹配后来复用同一栈槽的新激活。目标已失效时由 runtime 报告 control-error。

跨函数 block 落地后解除退出点并合流多值结果；函数内的 `return-from` 仍直接
跳转，途中显式离开退出点并执行 cleanup。跨函数 `go` 只携带目标段下标。
它的 landing 在读取下标、边复制和 poll 之前重新链接同一退出点，然后通过
MIR 条件边分派到对应段。这样同一闭包可在一次 tagbody 激活中连续退出多次。
普通段间流动与本地 `go` 保持区域活动，tagbody 正常结束时才解除退出点。
这些 landing 同样使用 cell 保留可写词法状态，并保留实际 cons 字段操作。

special 变量的引用必须读取当前动态环境，词法 SSA 参数不能代替它。构造器为
每个绑定点分配独立的区域编号，用显式进入和离开操作包围绑定的有效范围。
初始化式在进入前求值，嵌套绑定按后进先出的顺序恢复。函数参数先完成默认式、
声明检查和 supplied-p 的求值，再建立对应的动态绑定；可选和关键字参数在提供
与缺失两条路径合流后进入同一个区域，使后续默认式看到已绑定的先前参数。

验证器沿 CFG 传播活动区域栈，要求每个可达合流的输入一致，拒绝重复进入仍
活动的区域、恢复非最内层绑定和带活动绑定的普通返回。`return-from` 和 `go`
在跳转前显式离开目标作用域之外的绑定；循环重新进入已经离开的绑定点仍合法。
帧替换原语不能在活动绑定内使用。降级沿用 context 的 TLS 绑定表与动态区域：
正常路径离开区域时恢复旧值，调用中的错误或外层非局部退出由 unwinder 恢复。
函数级栈对象的根区域包围这些动态绑定，退出绑定不会撤销仍需存活的局部根。

动态绑定能让被调用的未知代码读到所绑定的对象，因此绑定值按堆存储边界参与
逃逸分析，不能把栈 cons 或栈闭包写进 TLS。special 读取保持未知类型，即使它
刚从某个已知类型的参数建立；中间调用可能改变动态值，后续读取仍须重新发生。

`progv` 在运行期才知道要绑定哪些符号，不能把它展开为固定数量的 special 区域。
构造器先按顺序求出符号列表和值列表，再用 MIR 循环检查两个列表以 NIL 结束，
最后检查符号列表的每个元素。检查全部通过后才进入一个动态 `progv` 区域；
任何检查失败都不会留下部分绑定。检查循环的游标通过独立的对象块参数传递，
回边沿用普通 CFG 的 poll 点，不占用源程序的词法绑定槽。

`progv` 与固定 special 绑定共享活动区域栈，因此嵌套恢复、局部跳转和普通返回
使用同一组验证规则。降级使用现有 LIR 入口：先把全部旧 TLS 值保存为受根保护
的列表，再链接动态条目，最后安装新值。值不足时对应符号在区域内未绑定，
多余值不参与绑定；重复符号按列表顺序写入，离开时仍恢复进入前的状态。
正常离开显式恢复，错误及外层非局部退出由 unwinder 恢复。符号和值列表及其
可达对象按堆存储边界参与逃逸分析。

`load-time-value` 的值在模块初始化时建立，不能把引用当作常量表达式重复执行。
构造器独立收集初始化函数，为每个引用节点分配单元内的 cell 索引。嵌套初始化
先于使用它的外层初始化；同一个节点的引用共享 cell，不同节点和不同模块实例
各自初始化。初始化表独立于函数 CFG，因此不可执行分支中的引用被优化掉后，
加载期效果仍然执行。初始化函数在空词法环境中接收零个参数，验证器拒绝捕获
环境、私有参数前缀和不匹配的入口，并检查读取指令的 cell 索引。

降级为每个初始化项建立静态 GC root cell，在执行顶层入口前依次调用初始化函数，
只保存主值；零个值保存 NIL。读取指令返回一个对象，类型保守为未知。返回的
可变对象或闭包因而保持身份并可跨 GC 存活，不会把初始化期间的栈对象留在 cell
中。包含这些 cell 的模块禁止初始化重放缓存，以免跳过效果或跨实例共享状态。
初始化表属于单元布局，单函数 pass 不能改变它，单元分析缓存也包含表的快照。

可选参数的默认式可能修改先前参数、调用函数或局部退出，因此入口不能把它们
概括为参数上的类型标记。函数记录必需参数数和可选参数数，先检查实参数量，
再逐项根据参数计数分支：已提供时读取实参，缺失时执行默认式，随后合流完整
绑定状态。`supplied-p` 来自是否提供该位置，显式传入 NIL 仍为真。参数声明在
各自绑定时检查，默认式按源程序顺序执行。

局部调用的输入摘要覆盖全部位置参数。已知缺失的可选位置按入口补齐的 NIL
传播，默认式产生的值另沿缺失分支传播。多值调用中，未知个数之前的完整已知
值组按固定位置传播，之后的位置保守使用未知类型。
当前分析汇合两条入口分支，尚不根据调用点的参数计数排除其中一条。

`&rest` 入口只检查实参数量的下限。实参区可能被声明检查或默认式中的调用
覆盖，所以入口在这些操作之前将额外实参保存为私有列表；可选参数默认式结束后
再绑定 rest 变量并检查声明。列表沿 SSA 传播，类型为 `list`，调用摘要仍只为
固定位置参数维护独立的输入事实。验证器要求 rest 构造在入口恰好出现一次，
位于数量检查之后、其他可能分配或调用的操作之前。函数入口没有前驱，
循环不能重新进入依赖原始实参区的入口操作。

`&key` 使用同一入口堆列表保存关键字尾部。列表长度检查、名称检查和查找
展开为 MIR 的循环与条件边，错误分支保留显式参数错误操作；所有回边经过 poll。
列表先按两个元素一组检查长度，再按最左边的 `:allow-other-keys` 值决定是否
拒绝未知名称。`&allow-other-keys` 允许未知名称，但仍检查尾部是否成对。
显式指定的非 keyword 包符号也可作为关键字名称。

关键字默认式可以读取并修改 rest 列表。若在每个默认式之后才查找下一个参数，
这种修改就会改变后续参数的原始实参。因此构造器先保存所有关键字参数的首个
匹配值和提供标志，再按参数顺序绑定和检查声明，缺失时才执行默认式。临时
游标、匹配值和提供标志使用独立的绑定槽，合流时与普通词法状态一起转为 SSA。
默认式对先前参数的赋值以及局部退出也进入同一 CFG。

关键字尾部保持堆列表边界，实参自身暂不参与借用证明；固定位置参数仍可借用，
默认式引用、保留或返回它们时按通常的 SSA 和调用摘要传播。

- `hir-to-mir` 接受一个 HIR 函数，返回已验证的函数单元。
- `verify-mir` 检查编号所有权、边参数、表示、效果下界、入口数量检查及 SSA 支配关系。
- `print-mir` 输出编号、块参数、操作、效果、源码和策略，供调试查看。
- `compile-module` 默认继承 `kiln.compiler::*compiler-pipeline*`，初始值为 `:mir`；
  原生编译只支持 `:mir`。
  `bootstrap-stage0` 的 `:pipeline :mir` 及构建脚本的 `KILN_BUILD_PIPELINE=mir`
  选择整模块 MIR 构建；各阶段与产物比较见 [bootstrap.md](bootstrap.md)。
  允许优化且未指定 `notinline` 的全局内建函数使用公共原语发射器；
  参数是否逃逸仍由 MIR 的调用和存储
  分析决定。常量函数名的 `(setf fdefinition)` 检查函数对象后直接写函数 cell，
  并在通知函数已安装时发送定义变更通知，使 kernel 能在运行期 setter 安装前
  建立自己的函数定义。`tools/test-mir-kernel.lisp` 从源码编译 MIR kernel，再运行
  依赖模块，验证初始化、普通及 setf 函数定义和重定义。
- 运行期动态绑定 `kiln.compiler::*compiler-pipeline*` 为 `:mir` 后调用原生 `compile`，
  选择该动态范围内的原生编译；嵌套编译和转换期间生成的辅助函数继承相同选择。
  默认的 `compile`、原生 `eval`、`load` 及 FASL 编译均使用 MIR。

`mir-analysis` 按函数修订号缓存分析。图修改统一经 `lisp/mir/pass.lisp` 的
`mir-run-pass`、`mir-run-passes` 或 `mir-run-unit-pass`。函数体修改声明 `:changes`，
可选类别为 `:instructions`、`:values`、`:control-flow` 和 `:bindings`；默认 `:all`。
指令类别包含操作数、效果、源码及块内顺序；值类别包含 SSA 定义、块参数和边实参；
控制流类别包含块集合、终结种类、区域和后继；绑定类别包含绑定表、策略和调试名。

框架在回调前后都推进修订并集中失效分析。修改中的图不使用正式缓存：每次分析
查询建立短期只读上下文，依赖分析仅在本次查询内共享；回调继续修改图后，下一次
查询重新读取当前状态。回调中计算或显式验证产生的中间事实不会进入稳定修订。
目前仅在控制流未变时保留可达、支配、环和 poll 集合，未知分析和只读视图始终失效。pass 不直接指定保留哪些缓存。函数编号、入口或捕获布局变化使用单元 pass。活跃修改范围按栈保存；即使经过另一独立单元的嵌套回调，也不能再次修改仍在栈中的单元，查询外层图时仍使用短期分析上下文。单元 pass 同时跟踪进入时和当前的函数成员，覆盖修改期间移出或新增的函数。

`*mir-check-pass-contracts*` 启用开发期审计，在每个回调前后比较所有函数的自有图
字段，拒绝未声明类别的修改及其他函数体的修改。常量对象属于语言数据，不遍历或
复制其内部内容；pass 不得修改共享 HIR、声明和 literal 对象。审计默认关闭，结构、
签名及私有入口验证始终执行。失败变换不回滚，发生内部错误的单元应丢弃。

分析查询要求当前图结构合法；变换应优先从稳定快照收集计划，再修改图。
单元分析使用独立的修订号，任一函数或单元 pass 在变换前后推进它。类型查询可凭
此修订号复用单元分析，避免逐次复制函数集合及修订列表。调用特化、谓词折叠与
局部函数改写可能暴露新的调用或分支。整轮修订号相同时，编译器跳过后续重复扫描。
启用 pass 观察器时仍报告每个阶段。
`mir-run-passes` 接收预先收集的函数体改写，分别在回调前后推进修订并失效分析，
完成后验证各变化函数，统一检查单元签名和私有入口。彼此独立的谓词、容器调用、
标量替换和参数化简使用该批次边界，避免逐函数重复检查整个单元；标量替换的
计划也从同一份调用和存储证明生成。`mir-run-pass` 是单个改写的入口。
单函数 pass 只改写指定函数体。改变入口或捕获布局会同时影响其他函数的调用与
构造点，因此接口为单元内所有函数保存独立的签名快照，拒绝函数集合、入口
参数及捕获布局的变化；原地修改布局向量也会被发现。这类变化使用
`mir-run-unit-pass` 协调更新各函数，并使全部分析失效。

HIR 建图完成后执行完整单元验证。优化器通过 pass 接口修改已验证的图，
函数体 pass 验证变化的函数，单元 pass 验证整个单元。LIR 发射读取这些
pass 验证过的图，共用其中缓存的分析结果。

私有函数值不逃逸是跨函数契约，本函数的 SSA 验证成立并不足以证明它。
单函数 pass 完成后也重新检查单元内的私有入口逃逸关系。完整单元验证先检查
所有入口布局，再验证函数体，避免调用方读取尚未校验的被调方签名。
验证器还计算可达性和支配关系，以检查 SSA 值的使用关系。

构造器用完整的词法环境位置连接循环、分支和异常入口，但未被读取的位置只保存
负编号占位符，不分配 SSA 值。函数图完成后，从指令和终结点的实参反向追踪
入口边，按需求物化绑定参数，再同步压紧块参数与边实参。占位符只存在于构造期，
不会进入验证后的 MIR。这样未使用的环境转发链不会产生庞大的 SSA 值集合。
剩余参数中仍有许多只是转发同一个支配值。因此
`mir-optimize-unit` 在首次类型和调用分析前先运行 `mir-simplify-block-parameters`：用
支配值替换一致的入口实参，沿实际指令和终结点的使用反向保留必要参数，再
同步改写边实参并压紧 SSA 编号。条件边通过目标参数保存细化后的类型，即使
所有入值相同，这些参数也不能在类型分析前合并。早期清理先解析完整复制链，
再保护承载条件值及谓词操作数的目标参数，并重新选择其余别名；这样也能识别
在较早块中计算、经中间块传来的谓词。循环中的不同入值和并行交换继续保留
参数，指令、声明检查、动态区域及 poll 不因这项清理而删除。清理按通常的图改写规则
使分析缓存失效并重新验证；内联、提升和标量替换之后再执行一次，去除这些
变换新产生的冗余参数。

条件折叠和内联可能切断原来的控制流，例如被调函数始终非局部退出时，调用后的
连接块就不再可达。若继续保留这些块，其中的捕获写入和私有调用仍会接受验证，
但可达路径上的函数身份分析无法为它们提供事实。因此这两种改写在验证前调用
`mir-prune-unreachable-blocks`，删除不可达块，并同步压紧块、SSA 值、指令和动态
区域编号，使函数及单元的分析缓存失效。可达块内的操作全部保留，单元中的函数
和加载期值表也保留。即使闭包构造点已被删除，留下的函数体仍可能按公开入口读取
所捕获的函数，因此公开入口判定也检查函数的捕获布局，避免单独改变这些目标的 ABI。

局部主值类型和多值事实由同一次固定点求解产生，按函数修订共同缓存；查询任一
结果都会建立两者，避免先查类型、再查返回个数时重复求解。

`mir-infer-types` 按 SSA 值编号缓存主值类型。常量和函数对象提供初始事实，
赋值、单值 bundle 和取主值操作传递事实，块参数汇合所有可达前驱的实参类型。
固定点迭代覆盖循环回边，不可达前驱不参与合流。CL 标准函数的类型规则接收
实参的 SSA 类型，推导二元算术、增减、位运算和部分容器操作的主值类型；
`values` 和 `identity` 转发主值事实。`lisp/type-inference.lisp` 提供类型域、
函数规则与声明投影等纯函数；MIR 求解器负责将它们应用于 SSA 值和控制流。

循环回边和内联复制的块不一定按数据流方向排列。每次类型变化都重扫整张图，
会反复计算尚未获得新输入的指令。类型求解器因此按图版本缓存 SSA 值到使用块
的索引：指令操作数、边实参及条件边读取的比较操作数都参与索引。所有可达块
先入队以建立初始事实；主值类型或 bundle 事实改变后，只将使用它们的块加入
工作队列，重新计算该块的指令和出口。待处理标记避免同一块重复排队，代价是
需要保存额外的使用关系。图改写推进版本后，下一次求解会重建索引。

比较结果的类型可能一直是 boolean，但比较操作数的区间仍会扩大。条件边因此
直接依赖这些操作数，即使比较和分支位于不同块，也必须重新传播收窄结果。
相应的跨块传播、版本失效和块顺序测试见 `tools/test-mir-type-worklist.lisp`。

条件边将测试所证明的事实传给目标块参数。谓词为真的边使用 CL 标准谓词的
类型；直接测试值为假的边将该值的主值收窄为 `null`。整数比较在两侧均有有限
区间时，按 `<`、`<=`、`>`、`>=` 和 `=` 的结果收窄对应操作数，真、假两条边
分别处理；反转操作数时也反转比较方向。无法表示的差集和不可能边仍保留保守
事实，不在此阶段删除控制流。

这些事实绑定到被测试的 SSA 值，而不是变量名。分析沿单值包装、取主值和声明
检查追溯主值身份，再与边上的实参匹配。测试之后发生赋值时，新值有另一个
SSA 编号，不会继承旧值的分支事实；合流块仍汇合所有可达前驱。未知谓词和
image 中可重定义的函数不提供条件事实。

算术运算会让循环中的整数区间不断扩大，因此每个 SSA 值在区间第二次扩大时
改用有限的表示边界。区间仍落在 fixnum 范围内时，扩宽到完整 fixnum 范围，
或保留已知的非负下界。后续输入超出这个边界时，非负整数继续扩宽为无位宽限制的
`unsigned-byte`，其余扩宽为 `integer`。越过有符号 64 位边界时也采用无位宽
类型。这让递增计数、捕获字段和 cell 内容保留已经证明的符号或表示，同时确保
传播会收敛。连续的 `unsigned-byte` 与有界整数声明取交集，保留区间的非负部分。

对从零开始、每次只递增一的计数器，若所有回边都经过同一个上界测试，
MIR 可直接推导计数器的区间。继续执行时计数器严格小于上界，下一轮的值
至多等于上界。对循环外的其他入口逐一验证初值，对回边逐一验证递增，
因此固定点可以用这一范围代替逐次扩宽。结构证明按函数版本缓存。
若简单特化向量的构造正常返回，而且构造支配循环头，MIR 还可用向量长度的
表示上限收紧计数器。循环上界与构造的长度参数必须来自同一个函数入口值，
这样后续迭代及可变绑定的写入不会把证明用到另一个长度上。

`unsigned-byte` 包含任意大的正整数，不能用它证明 fixnum 或任何有限位宽。
非负整数的加法、乘法、递增和适当的位运算保留该事实；递减或汇合负数会退到
一般整数。原子字节类型及其无位宽形式可直接投影到该域，有限位宽仍要求独立
上界证明。类型事实只用于已经完成固定点迭代的图。

声明检查接收一个 `obj` 或 `bundle`，返回同表示的新 SSA 值。分析在检查结果上
求输入类型与声明的交集，原来的输入值保持原有事实，因此检查后的类型不会
影响更早的使用处。参数绑定、局部初始化和赋值使用检查结果，`the` 返回检查后
的 bundle。bundle 的检查只约束主值，仍保留原来的返回值个数和其他值。

LIR 发射前使用完整固定点结果省略已证明成立的声明检查。需要执行 bundle
检查时先恢复主值供 `typep` 使用，再转发原先保存的载体与个数；检查调用可能
覆盖借用的多值区，不能从那里重新构造返回值。验证器要求检查的输入输出表示
相同，类型事实只属于检查正常返回的结果。

`mir-function-identities` 在 SSA 上跟踪局部函数编号。函数对象提供身份，赋值、
主值包装、声明检查和 CL 的 `identity`、`values` 转发身份；块参数的所有前驱
必须同意同一个编号，否则结果为未知。无词法数据捕获的 `flet`、`labels` 可以
直接使用这些函数的静态对象。函数绑定的环境依赖按固定点传播；只有无环境的
目标才可省去捕获槽，引用动态闭包的函数仍须捕获对应对象。

闭包构造先列出已解析的跨函数绑定依赖，并遍历赋值节点判断哪些捕获需要
共享 cell；不沿用 HIR 的 cell 或静态环境标记。只读捕获保存当前值，可写捕获
在绑定建立时分配一个 cell，后续读写显式操作该 cell。每次执行绑定都产生
新的 cell，循环中生成的闭包因而各自保留所属迭代的绑定；同一绑定的多个
闭包则共享修改。当前 cell 以 cons 承载，内容保存在 car，句柄只可用于
cell 读写、相应的环境槽和已验证的私有入口前缀，不能作为普通 Lisp 实参或进入多值 bundle。

捕获环境若始终只用于已知局部调用，保留闭包对象会增加分配和字段访问。
`lifting.lisp` 将这种函数的捕获值改为普通参数前缀，原有位置参数随后接收；
环境读取变成参数读取，构造点改用静态函数对象，环境字段写入消除。
调用点直接传入原先构造环境时保存的 SSA 值。函数值经过复制、条件合流或循环
回边时，其每个捕获槽都通过额外块参数和对应边实参传递，因此不同动态实例的
捕获值仍各自保留，不能仅凭函数代码编号选择某个构造点的环境。

提升要求函数对象没有逃逸或身份观察、函数及构造和调用所在函数均允许低调试
策略优化，且所有已知调用的实参数量都能证明处于源入口允许的范围。错误参数数量
的调用保留原入口，错误仍按源函数的参数数量报告。参数前缀计入入口接收容量和
每个调用点的后端实参数量上限。每个函数为环境新增的块参数默认限制为
4096 个，未通过预算证明的入口保留闭包路径。

入口支持必需、可选、rest 和关键字参数。可选参数的提供测试与位置读取同时
加上前缀偏移，显式 NIL 仍算已提供。rest 快照的起点也向后移动，因此关键字
扫描只看到用户实参，捕获值不会进入 rest 列表。默认式、关键字值快照和声明检查
继续使用原来的 CFG，保留默认式之间的赋值、调用和错误顺序。
多值调用把捕获项记录为独立的固定前缀，原有值组的求值指令及保存载体不变。
LIR 只把用户值组聚合进参数列表，再由列表调用的固定前缀接口传递捕获项；
因此栈上 cell 的句柄不会被写入堆上的收集列表。已知返回个数提供精确的
实参数量，未知 bundle 按零到
后端多值上限估计。只有整个数量区间都满足源入口范围，且增加前缀后仍不超过
调用参数上限时，才提升该函数。未知个数之前的完整已知值组仍为调用输入提供
类型事实，后面的参数位置保守处理，避免提升后丢失捕获前缀的类型证明。
共享 cell 虽以对象布局承载，句柄仍不应变成可由 Lisp 代码操作的 cons。
私有入口记录前缀长度与 cell 参数位图，参数读取和跨块环境字段保留 `cell`
表示。验证器从实际 callee 的 SSA 身份检查每个参数位置，拒绝伪造或未初始化的
句柄，并检查私有入口函数对象没有逃逸。

捕获的函数绑定可以传递实际函数对象，也可以在私有函数组内展开其环境。
仅保留代码编号会丢失该对象自己的环境，尤其是同一代码的多个闭包经过分支
合流时。公共入口继续以实际函数对象作为普通前缀参数，沿 SSA 边保留实例差异；
跨调用函数目标传播只恢复代码身份，不替代对象本身。

自递归和互递归函数通过捕获槽引用彼此，若一律把这些引用当作逃逸，就无法
消除整组闭包。`lifting-environments.lisp` 先按外部用途、策略、构造点和调用数量
求私有候选的固定点：函数对象只能作为已知 callee，或写入另一候选的已知函数
捕获槽；返回、身份观察、普通实参传递和公共闭包的捕获都保留公共入口。
没有构造点的函数体也参与捕获边界检查。

每个候选沿私有函数捕获边收集最终的数据及 cell 字段，以原函数编号和槽号
确定稳定顺序；递归边不再增加字段。构造点提供叶字段的实际 SSA 值，捕获边
则要求相同字段在不同路径上取值一致。字段沿这些约束传播到固定点，分支
合流通过新增块参数携带各实例的字段，函数自身的环境来自隐藏参数。
同一代码的两个实例可能带有不同字段，因此代码身份本身不能证明约束成立。
字段冲突时，被冲突字段所属的函数恢复公共入口，再重算其使用者；包装函数
仍可提升为传递两个实际函数对象的入口。

身份比较可以追溯主值来源，传参则保留原对象或 cell 的 SSA 值，避免把多值
载体当作字段。改写前检查字段定义是否支配新增的调用和边实参，并检查展开后的
入口、调用实参数量及块参数预算。全部检查通过后协调移除构造和捕获读取，
新增的隐藏参数读取放在入口参数数量检查之后。没有可共同提升的函数捕获时，
沿用直接环境提升，避免为普通数据闭包建立传递约束。

入口签名、构造点和调用点必须一起改变，单函数改写中途验证会看到不一致的
环境布局。单元级 pass 因而先推进各函数版本并失效全部分析，再协调改写，
最后验证整个单元。后续调用摘要和借用分析重新按参数前缀计算，让捕获对象的
逃逸结论与新的显式实参一致。

固定参数数量的私有自递归函数若每次都转发相同的捕获值，调用方可把捕获值和已验证的
简单向量底层存储一并放入堆向量。这个向量在进入递归前分配一次，递归调用只传递它
和会变化的实参。发射器在入口读取各字段，MIR 仍用原有的参数分析类型和边界。
调用分析要求所有调用点都能采用同一入口。借用和 cell 分析将写入堆向量的引用算作逃逸，
保证堆向量在 GC 时只持有合法的堆引用或立即值。直接读取或写入捕获的 cell 时，
发射器在访问点从环境向量取出 cell，避免为它在长循环中保留独立的活跃引用。


同一个局部函数接收不同调用点的实参时，函数级摘要必须合并这些类型，可能
丢失某个调用点已经知道的区间或函数身份。`inlining.lisp` 在局部函数提升后
展开满足预算的已知调用，让原函数体中的操作直接使用调用方的 SSA 值。
实参的计算留在原位置；复制函数体的块、边和定义，再将各条返回边接到保存
原调用结果的 bundle 参数上。循环的块参数和回边一起复制，因此参数赋值与
多值计数仍由同一套 SSA 规则约束。内联后重新计算受影响的分析并再次改写
类型谓词，使调用点的事实参与后续标量替换和表示选择。传入函数对象的形参
被替换后，还能显露新的已知局部调用。

内联器先按函数修订收集策略允许的调用点，没有候选时不请求跨函数分析。每轮
使用同一份函数流快照，为每个 caller 选择至多一个调用点，批量执行不冲突的
展开。批内修改的 caller 不能同时充当其他展开的 callee，保证复制源保持不变；
冲突延后到下一轮重新选择。增长预算逐 caller 累计，批次完成后才重算目标和
递归关系。这样独立函数的展开不会各自触发整个单元的求解和契约验证。

展开要求普通调用的参数数量正确、目标没有捕获或已将捕获提升为参数前缀，
并且目标不在已知递归分量中。调用点已经知道实参数量，
所以入口的参数存在测试改成常量，省略的可选参数仍沿原 CFG 求默认值和
supplied-p。rest 入口改为从已求值的实参构造 cons 链，位置保持在默认值执行前；
关键字快照和错误检查继续沿用原入口 CFG，避免默认值修改 rest 列表后改变
关键字实参的含义。
私有 cell 前缀直接替换为原句柄，共享关系不变；函数体构造的闭包和 cell 则
获得新的 SSA 定义。调用方已有的动态区域继续包围展开后的代码，目标中的
`throw` 和可能退出的调用仍按调用方的区域展开。`notinline`、不允许优化的
策略及高调试策略保留调用，错误参数数量继续由原入口报告。

被调函数自己的 special 绑定、`progv`、`catch`、`unwind-protect` 和词法退出区域
随 CFG 一起复制。区域编号原本只在各自函数中唯一，直接复制会让两次展开
或调用方已有的区域共享同一编号。内联器按调用方已有入口数量平移整组编号，
同步更新区域进入、退出、landing 和继续展开指令；正常及异常后继都指向复制后的
块。调用方原有的活动区域因此位于复制区域之外，正常返回先恢复被调函数的绑定，
异常退出则按内外顺序运行 cleanup 并继续展开。

帧替换尾分派不能直接保留在内联体中，否则它会移除调用方的帧，跳过原调用后的
代码。复制时将它改为普通函数对象调用，保留实参、多值结果和函数对象检查，
再经过通常的返回连接点继续执行。优化策略检查只约束可达终结点；构造阶段为
不可达占位块保留的默认策略不会阻止一个始终异常退出的函数参与内联。

为限制编译时间和代码增长，预算同时计入保留的指令、基本块和块参数，以及
返回连接点、缺失可选参数使用的 NIL 常量和 rest 链构造；默认单个目标的成本上限为 48，每个调用方的累计增长上限为 256。
原函数仍保留，其他调用和函数对象身份观察继续使用它。复制保留源码位置、
来源、策略和效果信息；每次改写推进调用方的修订号并验证图。


局部函数组先分配全部函数对象并保存在 SSA 值中，再填充捕获字段，支持自身
和相互递归的对象引用。堆分配会先将环境字段初始化为 NIL，因而填充期间发生
GC 也可安全扫描；函数在全部字段写入后才可普通使用。验证器检查环境大小、
字段表示、同块内的完整且唯一初始化，以及构造完成前不得观察函数。尚未建立
的 cell 绑定用专用占位句柄经过块参数，验证器沿边传播其未初始化状态，禁止
读取、写入或捕获这些占位句柄。

占位状态按 SSA 值编号记录，而值的数量可能远大于基本块数量。在目标运行时，
用宽整数记录这项状态会让单个位测试生成大整数中间结果。验证器因此使用
布尔向量记录状态，为可达边上的 cell 参数建立传播关系，再从占位定义启动
工作队列。每个新标记的值只入队一次，避免块编号顺序导致反复扫描整张图。
传播完成后检查读取、写入、捕获和传参；不可达前驱不参与合并，没有占位
定义的函数直接跳过传播。额外空间与 SSA 值和 cell 边数量成正比。

捕获的不可变局部函数绑定保留代码编号，验证器对照环境初始化值检查该编号，
调用图因此可以穿过递归闭包的环境读取。只读捕获的类型按代码的环境槽汇合
全部构造值，再传给环境读取和返回摘要。同一代码可以在运行时构造许多闭包，
所以不能用某一次构造的值特化所有实例；外部可调用的构造函数仍从未知参数开始。

共享 cell 的内容会随写入改变，不能沿用捕获时的类型。`mir-infer-cell-aliases`
先为 cell 分配点编号，沿 SSA 边、环境字段和私有调用前缀传播可能指向的 cell 集合；内部句柄
不能经普通参数或多值返回流出，因此这些显式边覆盖了已知句柄的传播。
同一分配点的所有运行期实例共用一个抽象身份，同名但不同的词法绑定分别编号。
没有构造来源的环境槽或私有 cell 参数保留未知 cell 标记；从未知 cell 读取返回未知类型，向它
写入时则扩大单元内所有 cell 的类型，不能假定它与已知分配点互不相交。

每个 cell 的类型汇合初始化值和全部可能写入，再沿读取进入通常的 SSA 类型
传播。多个闭包共享同一 cell 集合；提供和缺失参数的分支也可能让一个环境槽
指向多个分配点。事实不依赖最后一次写入或调用顺序，保留检查正常返回后才能
使用的声明类型。捕获槽与 cell 内容的整数区间使用同一 widening 规则，递增
回路不会无限扩大区间。跨函数修改同时使句柄别名、捕获类型和调用摘要缓存失效。

闭包值也进入 `mir-infer-storage` 的身份集合。词法转发、作为普通或多值调用
的 callee、对象身份比较以及接受任意对象的无保留谓词可以保持不逃逸；
返回、全局保存、多值堆载体和显式参数传递则退回堆。cons 参数的借用摘要
不用于函数对象：例如 `car` 可以读取 cons，却会把函数对象作为 type-error 的
数据交给 handler。无效字段访问和不能证明成立的声明检查因此也保留堆闭包，
保证错误处理程序保存的对象在创建帧退出后仍然有效。

闭包构造仍将普通捕获值作为堆边界，cell 的内容写入也保留同一边界。函数值
进入捕获字段、cell 或其他容器时使用堆存储；自身引用及递归组通过环境字段
连接，所以目前也保留在堆上。这个规则让闭包作为 callee 时无需假定 cons 的
字段借用证明适用于隐式 self，也不让被调用函数通过捕获值取得短命函数对象。

cell 句柄的用途由表示验证限制在读写、SSA 边、环境槽和私有调用前缀，因而
可沿跨调用别名集合检查全部捕获位置。`mir-select-stack-cells` 使用单元内的 cell 别名集合：任一堆闭包捕获
该集合，就使涉及的分配点全部留在堆上；所有捕获位置都是安全的栈闭包时，
cell 可以使用创建帧的栈槽。这个检查跨函数进行，较内层函数返回的新堆闭包
也会撤回较外层 cell 的栈存储。未知句柄按可能与所有已知 cell 相交处理。
cell 内容仍限于堆对象或立即值，避免内层调用把自己的短命对象写入较长寿命的绑定。

闭包及 cell 的栈存储要求创建函数和相关代码的 `debug` 小于 2，分配点不在
循环 SCC 中，并且创建帧没有替换自身的尾调用原语。函数入口初始化栈槽并
登记捕获字段或 cell 字段的精确根，实际构造时填入值，普通返回和异常展开
撤销登记。根覆盖整个函数，可能延长捕获的堆对象的存活时间；多个活动帧的
栈闭包可以共享较外层仍然活动的 cell。cell 消除、函数值的显式参数借用和
捕获对象的联合栈存储证明仍待扩展。

`mir-infer-calls` 根据已知目标建立调用图，以 SCC 顺序初始化工作队列。
实参和环境事实变化唤醒 callee，返回摘要变化唤醒 caller，cell 写入唤醒共享
该绑定的读取方，直到共同稳定。参数汇合所有数量正确的已知调用点，不为单次
调用单独特化；数量错误的调用仍在读取参数前退出。递归参数、返回值及多值
位置使用同样的整数扩宽规则。没有事实种子的参数、环境槽、cell 内容和返回值退到未知，再闭合一次固定点，
之后才发布优化事实。LIR 发射使用 `mir-infer-types` 的 unit 参数消费这些结果。
当已知调用图没有边、单元没有共享 cell 或捕获槽，且所有入口参数都取未知类型时，
各函数的类型与返回值可以独立计算。

局部函数可能经函数值从别处调用，不能只根据具名调用点收窄其参数。
分析用位集合跟踪 SSA 值及 bundle 中可能携带的局部函数，合流取并集，
`values` 包括每个返回值，取主值时保守保留整个集合。返回、全局写、声明检查、
普通调用的实参、原语实参和未知目标调用的 callee 都使其中的函数具有外部
调用入口；这些函数和 unit 的入口参数从未知开始。当前不在函数间传播参数
的函数身份，也不展开堆容器，所以传给已知 callee 或容器构造器的函数同样
按外部入口处理。普通 `identity`、`values` 只转发值，可继续跟踪。
这些集合用于判定参数入口是否封闭；存储选择还需跟踪堆字段、捕获和对象生命周期，
建立独立的逃逸证明。

`multiple-value-call` 保留一个 callee 对象和按顺序排列的 bundle 实参。
构造时先求 callee 的主值，再从左到右求各个返回值形式，每组值在下一组求值
之前保存。LIR 发射恢复各组值，依次追加到私有参数列表，反转后通过普通列表
实参调用入口调用函数；反转循环包含 poll。callee 的函数设计符检查发生在所有
返回值形式求值之后，调用结果仍按普通 bundle 保存。

已知局部目标的实参分析也按此顺序拼接各组类型。全部返回个数已知时，仅将
总数匹配签名的调用纳入参数摘要。某组个数未知时，前面的完整已知值组继续
对应固定参数位置，未知组及后续组所占的位置则保守合并未知类型。尚无 bundle
事实的调用等待固定点传播，不能把它误作零个实参。函数值包含集合覆盖各组值，用于外部入口判定。

跨函数缓存按 unit 修订号判断有效性。增加、替换或修改 callee 的 pass 在
变换前推进该修订号，使整个调用分析失效，不能只凭 caller 的修订号复用类型表。
入口块构造简单特化向量后，已验证的长度范围也可纳入直接局部调用的参数摘要。
调用须传入同一个 SSA 值，且入口块没有可能绕过构造的异常处理入口；同块调用
还须在构造之后。被调方可据此省去已证明安全的整数运算检查。

返回摘要只提供类型事实，调用仍保留原来的效果、参数数量检查和多值协议。

外部入口未经检查的参数、全局读、未知目标的间接调用、image 定义的全局调用和原语
调用结果保持未知。活 image 中的全局定义可变，使用其摘要需要守卫或依赖记录。
发射器不修改图。

局部函数经参数传入或作为主值返回时，只在单个函数内追踪 SSA 复制会丢失
调用目标。`mir-infer-function-flow` 因此先独立求出跨调用的代码编号：封闭入口
汇合全部已知普通调用的位置实参，函数的返回终结点汇合主值目标，再把结果
传播回调用方，直到稳定。未知目标与不同代码编号的合流得到未知；外部入口
的位置参数从未知开始。尚无输入的函数和没有初始事实的递归组先保留未见状态，
固定点结束后将其改为未知并重新求解，保证这些函数仍能生成安全代码。

这份事实表示函数的代码编号，不表示某个闭包实例。调用仍使用实际函数对象及
其捕获环境，同一代码的不同闭包不会合并。入口是否对外可见继续由独立的局部
逃逸分析保守判断；把函数传给局部调用仍会公开该函数的入口，已知代码编号不能
据此为它增加私有参数前缀。参数数量错误的普通调用不提供入口事实；缺失的位置
参数和 `multiple-value-call` 的位置输入保持未知，cell 内容和普通捕获值也不据此
推导函数目标。

类型与多值分析使用这份目标表建立调用图。内联器也使用它检查递归分量，回调边
因此参与递归判定；每批改写后按单元修订快照重算，避免沿用展开前的目标或递归
关系。模型检查见 `tools/test-mir-function-flow.lisp`，运行期检查见
`tests/m6/co-mir-function-flow.lisp`。

`mir-infer-value-facts` 给出 bundle 的多值事实，与主值类型共同迭代。
`mir-values-fact` 记录一个已知返回个数或未知个数，以及前 16 个位置的类型；
超过前缀的位置保持未知，但已知缺失的位置总是 `null`。前缀限制控制分析内存，
不限制程序返回值的数量。两个返回个数不一致时，个数合并为未知；逐位置的类型
按取值语义合并，缺失值补 NIL。递归中的每个位置单独记录区间扩大次数并 widening，
避免主值稳定而次值不断增长时分析无法收敛。

单值包装和有单值契约的 CL 函数提供个数 1，`values` 提供完整个数和前缀类型，
已知局部调用使用 callee 的多值摘要；未知调用的个数保持未知。声明检查只收窄
主值，保留原先个数和其他位置的类型，包括零个值的情况。

词法多值绑定将初始化式求值一次，使用 `value-ref` 指令读取保存的 bundle，
先把所有绑定值读入 SSA 值，再检查声明和建立绑定。声明检查可能调用 `typep`
并覆盖借用的多值区，所以后面的绑定必须使用已经保存的值。已知缺失的位置
直接生成 NIL；其他位置恢复保存载体并按实际个数取值。bundle 的原始个数保留
到返回和合流处，取主值或绑定多个变量都不会改变它。

普通 `list` 和 `list*` 调用隐藏了各个 cons 的身份，逃逸分析因此无法分别追踪
这些字段。局部调用内联之后，`lists.lisp` 将允许优化的短列表调用展开成显式
cons 链，供后续类型、逃逸和标量分析使用。全部实参仍先按原顺序求值，再从
尾部构造列表；`list*` 的尾部直接使用原对象，原调用的 bundle 定义保持不变。
每次调用至多展开八个 cons，每轮对每个函数至多展开十六个 cons；超出预算、
`notinline` 和低优化策略保留原调用。空列表及只传一个实参的 `list*` 继续使用
原发射器。模型测试见 `tools/test-mir-lists.lisp`。

`mir-infer-storage` 在 MIR 上建立 cons 对象图，使用 unit 的修订快照缓存证明。
每个 `cons` 调用点提供一个分配身份，SSA 值的位集合表示可能引用的身份；
位零表示来自图外的未知对象。字段读取、写入和逃逸传播只遍历接收者集合中
选中的本地分配点或形参字段，避免对每个稀疏集合扫描整个字段表。外部对象
和可能回退堆分配的 rest 字段仍使写入值按堆逃逸处理。`car`、`cdr` 沿字段关系读取，`rplaca`、`rplacd`
将可能写入的身份并入字段集合。字段事实不覆盖旧值，因此同一分析可以保守
处理分支和循环中的写入。

返回、全局写、未知调用和未证明成立的声明检查使相关身份逃逸。向未知接收者
写入字段时，写入值也必须逃逸。堆对象不能持有栈指针，所以任何需要堆存储的
对象都会传递地使其字段中的对象退到堆；多值堆载体及合流处的装入载体操作也
使用同一规则。已知单值保存在对象变量中，因而可以携带不逃逸的栈对象。

固定栈槽只能表示同一帧中的一个动态身份。分配块位于 CFG 的循环 SCC 时，
该调用点退到堆，防止多次分配覆盖仍存活的旧身份；循环之前分配的对象仍可
在循环中使用。对象字段可以形成环，字段闭包与 GC roots 会保留这些引用。
关闭优化的调用点及 `notinline cons` 保留堆分配，其字段也参与堆到栈检查。

选定的 cons 在函数入口建立独立栈槽，先初始化引用字段，再登记精确 roots；
普通返回逆序撤销登记，非局部展开由既有 runtime 区域机制清理。槽的生存期
覆盖整个函数，因此可能延长其中堆引用的存活时间。读取、修改和身份测试使用
已有原语发射，`identity` 和 `values` 直接转发值；`notinline` 的全局调用走普通函数
入口，其参数保守地视为逃逸。闭包的普通捕获值和 cell 内容保持堆存储边界，其他容器尚未接入此对象图。

`mir-scalar-replace` 在 LIR 发射前将只用于字段访问的 cons 提升为 SSA 字段。
没有 cons 分配点的函数不启动这项分析。单元的已知调用图没有内部调用边时，
存储选择也无需计算参数借用摘要。
不逃逸只能证明可以使用栈存储，不能证明可以删除身份：`eq`、条件测试、
函数调用或把对象写入其他容器都可能观察原对象。因此候选的每个用途都必须
是单值转发、已证明的声明检查，或确定接收同一 cons 的 car/cdr 读写。
对象集合中的空集合也可表示 NIL 等非 cons 值，所以另求一份“确定来自哪个
分配点”的事实，避免把 cons 与 NIL 合流后的读取当作无条件字段访问。

每个被提升的 cons 为非入口块增加两个对象参数，每条边传入该路径上的当前
字段值。初始化设置字段状态，修改替换对应字段的 SSA 版本，读取转发当前
版本；分支合流及循环回边因此保留读写顺序。原实参的求值和其他调用保留，
已有 poll 也保留。字段中的堆对象作为普通 SSA 对象参与精确根活跃性分析，
不再依靠已删除的 cons 保活。身份转发链只保留占位值，所有可能观察该值的
用途都会排除候选；已证明成立且接收确定身份的声明检查随身份一同移除。

这项改写只用于函数及全部局部指令的 `debug` 都小于 2 的情况，较高调试策略
保留实际对象。循环内的分配、歧义接收者、身份观察、跨函数传递和自引用保留
通常的堆或栈对象；包含其他对象的图尚不联合标量化。每个函数最多提升 32 个
分配点，附加字段参数最多 4096 个。改写通过修订接口撤销分析缓存，再验证
SSA；后续类型、调用和存储分析重新计算。

已知局部函数的参数可以在调用期间借用。`mir-infer-borrows` 为参数引入抽象身份，
同样经过 SSA、字段和载体传播；进入堆、全局或未知调用的参数失去借用资格。
直接返回一个参数或其字段可以保留借用，但必须把返回别名路径一并交给 caller。
caller 在自己的对象图中解释这些路径，因而返回子对象只会使实际涉及的身份
退到堆，不会把整个参数误作无关的外部值。

callee 也可能修改借来的对象。普通字段写入会使写入值涉及的参数失去借用资格，
callee 的局部分配若进入参数字段也必须使用堆；相同 SSA 对象写入自身时，则
保留该身份的自引用边。摘要记录接收者路径、字段和自身／外部值写入。caller
先将这些可能的写入并入字段图，再解释返回路径，避免把修改后的字段仍当作
原来的 NIL，进而向新出现的堆对象写入栈指针。

递归组从借用假设开始，只在全部相关参数、返回别名和写入效果共同稳定后使用
结果。发现外泄就撤销假设，返回路径与写入效果则在组间继续传播。字段路径最多
保留四层，超出部分概括为任意可达对象；每次路径分析的预算为 8192 次路径操作，
耗尽时该函数的参数全部保守地改为逃逸。跨函数修改使借用与存储缓存一同失效。

借用摘要覆盖必需与可选位置参数，调用点检查实参数量是否落在入口范围内。
缺失位置的返回别名及写入路径不在 caller 中解释；默认式引用先前参数的别名
仍沿 CFG 进入摘要，因此不能漏掉默认式造成的保留或返回。带 `&rest` 的局部
函数也可借用固定位置参数；额外实参进入堆列表，逐个视为逃逸。即使同一对象
同时作为位置实参和额外实参传入，也必须退到堆存储。

普通 `&rest` 的整条链和所有尾部共用一个抽象身份，car 初始指向外部实参，
cdr 指向同一抽象链。SSA、字段读写和局部调用按对象图规则传播；返回任意尾部、
进入堆容器、未知调用或非单值载体都会使整条链退回堆。链在入口只构造一次，
因此可以跨循环存活，运行时每个 cons 的实际身份仍各不相同。

证明链不逃逸后，LIR 为它提供八个独立 cons 栈槽，字段先初始化再登记精确根。
实参尾部不超过容量时使用这些槽，超过容量时整条链改用堆分配。栈根覆盖函数
执行，并随正常返回或非局部展开撤销；链中引用的堆对象可被移动 GC 更新。
带关键字的入口仍使用堆列表，关闭优化的策略和替换当前帧的尾调用原语也使
函数中的对象保持堆存储，避免帧被替换后遗留栈根登记。

容量回退意味着 rest 链即使不逃逸，也可能在堆上。向它的 car 或 cdr 写入另一个
对象时，该对象必须满足堆存储边界，不能把其他栈对象写进去。相同 SSA 对象
写入自身可保留自引用；局部调用中的字段写入和参数借用也应用同一规则。

这项证明只用于目标和参数数量均已知的普通局部调用，函数体仍通过正常调用
入口执行，局部 `notinline` 不妨碍使用摘要。多值调用的参数列表和其他堆载体
仍会存储对象引用，因此不会仅凭 callee 可借用就把其中的对象改成栈存储。

降级先利用活跃性省略未使用的常量、参数和计数加载，不为这些结果创建 LIR
变量。丢弃结果不代表可以丢弃操作：函数调用、声明检查和可能报错的访问仍执行。

退出 SSA 时为每条边建立独立的复制块，先准备载体转换，再按并行赋值的依赖
调度块参数复制。目标旧值不再被读取时可直接赋值；复制环只保存一个旧值到
同表示的临时量，再继续调度。自复制省略，bundle 的载体及个数共同参与调度，
覆盖临界边、自回边、交换和复制环。
函数入口使用后端的入口 poll，深度优先遍历中的回边目标块入口发射显式 poll。
删除所有选中的块后图为无环，因此普通回边、自回边和多入口循环均经过 poll；
同一循环的无关块不再重复检查。选择结果按函数修订缓存，使用显式遍历栈
避免深 CFG 耗尽宿主栈。入口标记
在 LIR 规范化时由后端入口检查接管，不能用它替代循环中的显式 poll。Rust 后端
继续负责 ABI、多值载体和精确 GC roots。

模型测试见 `tools/test-mir.lisp`，内联与增长预算测试见 `tools/test-mir-inline.lisp`
和 `tools/test-mir-inline-entry.lisp`，
cell 初始化传播测试见 `tools/test-mir-cells.lisp`，局部声明检查见
`tools/test-mir-scoped-declarations.lisp`；运行方式与 HIR 模型测试相同。
`tools/test-mir-lir.lisp` 使用 `tools/test.sh` 已生成的 kernel、CLOS 模块，验证
SBCL 从显式 MIR 入口生成二进制 LIR 并交给 JIT 执行。端到端用例在
`tests/m6/co-mir.lisp`，覆盖循环中的并行复制、多值跨调用保存、声明检查、参数数量

## 数据模型

函数、基本块、指令和值使用紧凑的整数编号，存在按编号索引的 simple-vector 里；节点本身是[原生结构对象](objects.md)，指令按整数 kind 分派。集合用位集合，工作队列用可增长向量。这些也是 [compiler-performance.md](compiler-performance.md) 要推的做法。

- 基本块参数表达 SSA 合流，终结指令列出全部后继和边上的实参。
- 绑定（HIR 的变量身份）、源码位置、策略和 SSA 值分开编号；循环里的一个分配点不代表所有动态对象是同一身份。
- 只有标量走 SSA。可变的堆字段、闭包共享的 cell、函数 cell、special 变量和动态环境保留显式的操作；内存状态不采用 Memory SSA。
- 语义类型和机器表示分开：一个值可以有整数区间事实，同时仍是装箱的 `obj`。

分析结果放在侧表里，带函数的修订号。修改 CFG、调用或存储的 pass 声明它使哪些分析失效，不能沿用旧的证明。

## 从 HIR 构造

输入是已经完成宏展开、绑定解析和声明处理的 HIR。构造按求值顺序把树变成块和边：

- 局部变量的读写变成 SSA；可写且被捕获或调试可见的绑定变成抽象 cell 操作，cell 怎么存由表示选择决定。
- `block`/`return-from`、`tagbody`/`go` 在同一函数内变成边，途经的动态范围在边上显式离开；跨函数的退出保留退出点和令牌。
- 可能退出的调用有正常边和退出边，结果只在正常边上可用。`catch`、`unwind-protect`、special 绑定、`progv` 变成带区域的操作；`unwind-protect` 的 cleanup 覆盖正常和非局部两种离开方式，cleanup 自己的退出覆盖原来的退出。
- 多值用显式的 bundle：取主值、转发全部值、保存和恢复分别表示，个数固定时拆成普通值。
- 局部函数组保留相互递归和捕获身份；已知调用引用函数编号。
- 声明引入的检查和位置作为检查义务保留，后续表示变化不能遗漏它们。

## 分析

- 可达性、支配关系、use-def、循环和调用图；递归组按 SCC 求摘要。
- 类型和整数区间传播：固定点迭代、widening，预算耗尽时回退到保守事实。CL 类型的含义通过既有类型系统判断；数据流事实仍需要区间、合流和 widening 等分析域，类型查询返回未知时保守回退。
- 局部调用身份、参数和多值返回的摘要，lambda lifting，按策略和增长预算的内联。
- 别名、对象包含关系、捕获和逃逸，用于 cons、闭包、rest 列表的存储选择。
- 装箱消除、整数和浮点机器值、运行期检查和显式慢路径。

效果摘要分别记录堆和全局的读写、动态环境访问、分配、GC、可能退出和未知调用。结果没被使用不能证明操作可以删除；删除分配还要证明身份、错误和调试器能观察到的行为不变。未知调用、不透明类型和动态退出扩大效果和逃逸集合。

活 image 里的全局函数可以重定义：调用全局函数默认读函数 cell；直接调用、内联和布局特化需要语言保证（CL 函数不能重定义）、守卫或依赖记录（[dependencies.md](dependencies.md)、[specialization.md](specialization.md)）。守卫失败走显式的普通路径。seal 后才使用冻结世界的更强证明。

## 类型驱动的改写

MIR 在 Lisp 里，所以类型推导之后可以生成 Lisp 形式再拼回来：改写函数拿到调用点的实参类型，返回一个 lambda 形式，经 HIR 转换（在定义环境里，带依赖记录）、构造成 MIR 子图，替换原调用，然后让受影响的分析失效。这是 SBCL deftransform 的做法，适合 `append`、序列函数、`typep`、CLOS 调用点特化这类改写（当前由 MIR pass 和发射器中的专门规则实现，见 [lowering.md](lowering.md)）。编译器宏照旧在 HIR 转换时展开，此时没有类型信息。

## 身份和存储的证明

- 标量替换要求对象身份不可观察，字段别名和写入都已纳入分析。
- 保留身份的栈存储要求对象及其可以到达的引用不越过本帧或动态范围；未知调用、返回、全局存储、堆容器和捕获都可能逃逸。rest 尾部、对象字段和闭包捕获要传递地检查。
- 循环重入、对象比较、可变字段和调试器观察必须参与证明；不能让一个分配点的多个身份同时存活在同一个栈槽里。堆对象不能指向栈对象。
- 无法证明时保留堆分配和装箱。`dynamic-extent` 声明也走同一套证明。

证明的结论在 LIR 里表现为 `stack` 存储和 `word`/`f64` 变量，Rust 信任它们（[lir.md](lir.md) 的“原则”）。

## 参数绑定

参数数量、optional/key 初始化、supplied-p、rest 及声明检查由 Lisp 转成普通控制流，默认式的副作用与退出参与同一分析。LIR 只保留参数计数、实参读取和 rest 构造操作；Rust 根据 ABI 实现这些操作。

## 表示选择和输出

表示选择决定每个值是 `obj`、`word` 还是 `f64`，插入装箱和拆箱；决定 cons、闭包、cell、rest 列表的存储；完成闭包转换（捕获什么、内部入口的捕获项前缀）；把个数固定的多值拆开。然后退出 SSA，块参数改成边上的并行复制，拆分临界边并用临时量解决复制环，输出 LIR。

## 验证

构造之后、结构改写之后、输出 LIR 之前运行验证器：编号、SSA 支配、边的实参、终结指令、捕获关系、多值协议、区域嵌套、调用签名和策略来源。验证失败是编译器内部错误，不发布部分代码。

## 和 HIR 求值器的关系

HIR 求值器（[hir.md](hir.md) 的“编译期求值”）照旧直接在 HIR 上构造闭包，不经过 MIR。两者共用绑定、参数协议、声明和退出的语义。

## 分析与验证的生命周期

MIR 分析用 `hir-buffer-view` 借用只读快照，同一函数或单元修订中的分析共享
这些快照，追加元素后按计数刷新。图变换撤回快照命名空间，验证建立独立的新鲜
命名空间，因此直接修改缓冲区后的验证仍能发现错误。`hir-vector` 继续返回
独立副本，已有 HIR 调用方可以修改它而不影响缓冲区或分析视图。快照只复制
元素引用，指令和块的内容仍由图修订管理，借用方不得修改快照的元素位置。

可达性只需从入口沿边遍历；求支配关系还要执行固定点迭代。仅查询可达块的
分析独立缓存可达集合，避免把支配计算附加到类型、身份和存储查询上。

验证器在一次稳定图的验证期间共享函数身份结果。整个 unit 验证和局部 pass
完成后的验证分别建立独立上下文，闭包字段、内部调用和私有入口检查复用
同一结果。验证器还发布本次新算出的可达性、支配关系和动态绑定状态，供同修订的参数
化简、提升与降级复用；验证自身仍重新求解，并不信任这些缓存。
下一次验证重新计算，因此直接修改图后的独立验证不依赖优化器
缓存是否已失效；变换仍通过 pass 接口管理优化分析的修订。

块参数别名求解为每个入口实参建立依赖参数索引。某参数被一个支配值替代后，
只将依赖它的参数加入工作队列，并把这些依赖移交给新的根。这样反向编号的
长转发链也不需要逐轮扫描所有块；候选冲突、循环自引用和支配条件仍参与判断。

局部函数身份和函数值包含集合按 SSA 使用块传播变化，与类型分析共享显式操作数
和入边实参的依赖索引。类型分析另外登记条件收窄隐式读取的比较操作数。
反向编号的块和循环只唤醒读取新事实的块，不再逐轮扫描未变化的函数体。
函数值包含集合只依赖本函数体和捕获布局，按函数修订缓存；其他函数改变导致
单元调用摘要失效时，这份结果仍可复用。独立验证重新计算，不读取优化缓存。

函数身份的跨函数固定点按依赖调度。实参身份变化只唤醒对应被调函数，返回摘要
变化只唤醒已知调用方；新发现的调用目标登记反向依赖。未调用入口和无初始种子的
递归组仍把底值提升为未知，再传播到使用方，保证公开入口的代码安全。

跨函数类型求解分别登记返回摘要的调用方、形参和捕获字段的所属函数，以及共享
cell 的读取方。某项事实扩大时只唤醒这些依赖方；类型与多值摘要保留原有的
扩大限制。每次处理函数时保留其主值和多值结果；依赖队列收敛后直接发布最后
一轮结果，只把局部未获种子的主值底值改为未知。任何形参、捕获、cell 或被调
摘要变化都必须先唤醒消费者，因此发布时不必再从头求解所有函数。

参数活跃性沿已索引的入边反向传播：实际指令与终结点的使用作为种子，每个新活跃
参数只处理自己的实参。不可达前驱也保留在该索引中，使仍存在的死 CFG 边继续
具有合法实参；别名证明则只使用可达前驱，避免死边影响支配值选择。

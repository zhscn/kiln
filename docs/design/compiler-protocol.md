# Lisp 与 Rust 的编译协议

编译协议把一次编译描述为封闭请求：Lisp 完成环境相关工作，Rust 消费不可变的语义数据并返回产物。协议不要求 Rust 访问 Lisp 堆，也不要求 Lisp 了解 MIR 的内部布局。此协议是目标设计，尚未实现。

## 请求

请求头包含协议版本、目标架构、runtime ABI 指纹、编译配置和优化管线版本。主体由带长度的记录表构成，采用会话内稳定 ID 引用函数、绑定、退出区域、节点、来源、literal、类型描述和依赖假设。Rust 结构体内存布局不作为线格式。

主体包含绑定后的 HIR、参数协议和捕获关系、声明检查义务、策略、源码与宏展开来源、归一化原语及效果签名。可用内联体在 Lisp 的定义环境中预先展开并解析，携带依赖和 `notinline` 限制；Rust 决定是否克隆。候选缺失时保留调用。

宏函数、编译器宏和类型展开器只在 Lisp 阶段运行。不能导出的类型事实使用不透明检查描述或普通运行期调用；不能把一个环境回调当作缺省查询接口。原语编号、参数和效果受协议版本校验，未知的必需操作拒绝导入。

## 两个前端适配器

SBCL 适配器导出可移植数据和常量对象图，不能把 SBCL 的 tagged word 交给 kiln runtime。必要的 `make-load-form` 初始化先转换为可编译的语义描述，保留创建、填充和共享顺序。

kiln image 适配器为现存对象分配 literal ID，用作用域 root frame 持有对象。请求中的 ID 不随移动 GC 改变；Rust 优化只操作 ID 和归一化事实。代码安装时将仍使用的对象转交产物的持久 roots，然后才能释放请求 roots。失败、取消和依赖失效都释放暂存产物。

适配器共享语义 schema 和验证样本，但分别承担宿主对象与目标对象的转换。编译期副作用按源顺序发生；请求生成后 Rust 的纯分析可以独立执行。

## 返回值与发布

返回结果包含结构化诊断、KIR 产物、仍使用的 literal ID、初始化计划、源码及调试元数据、依赖假设。初期沿用现有 KIR 和 FASL 载荷；MIR 不成为必须持久化的新文件格式。

安装层校验目标、ABI 和依赖版本，登记代码、异常表、栈图与 roots，最后发布定义。校验失败时丢弃未发布产物；需要重新展开的编译由 Lisp 调度，不自动重放宏或其他编译期副作用。Rust 的纯分析重试和 Lisp 的语义阶段重执行是不同操作。

协议返回诊断和状态，跨 ABI 的运行期错误与非局部退出使用 [interop](rust-interop.md) 的完成协议。Rust panic 在 Rust 入口边界转换为编译器故障，不穿过 Lisp 或 C 栈帧。

## 编码、生命周期与确定性

传输采用批量、自含的缓冲区和显式长度，检查索引、整数溢出、递归深度和资源上限。谁分配缓冲区，谁提供释放入口；借用只在调用期间有效。服务 ABI 与编译 schema 分别版本化，版本不匹配在处理主体前拒绝。

编号按稳定遍历顺序分配，不能依赖地址、哈希表迭代或宿主 gensym 计数。literal 的共享和合并遵守对应编译模式的身份规则，不能因内容相等而改变 image 中可观察的 `eq`。`load-time-value` 初始化单元保持独立身份。

缓存键包含规范化请求、目标、配置、ABI、管线版本和依赖；涉及 image 对象时还需对象身份及有效期描述，不能缓存裸地址。缓存不能省略语言要求的编译期效果。

协议提供独立导入验证器、可重放请求和结构化输出，供 Lisp 前端与 Rust 中端分别开发。互操作封装先实现 roots、所有权和退出边界，再接入完整优化管线。

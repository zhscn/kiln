# 降级：HIR → MIR → KIR

目标降级由 Rust 负责：将 Lisp 导出的语义 HIR 转成 MIR 控制流和标量 SSA，再选择表示并降级为 KIR。当前实现仍由 `lisp/hir/lower.lisp` 配合 `lisp/lower.lisp`、`lisp/values.lisp` 和 `lisp/primitives.lisp` 直接生成 KIR；迁移以这些实现的语义行为为参照。总体分工见 [编译器架构](compiler.md)。

## HIR 到 MIR

输入已经完成宏展开、绑定解析和声明处理。Rust 将求值顺序转成基本块和边，建立 SSA 合流，保留源码、策略及检查义务。Lisp 导出器不预先选择 tag、对象偏移、KIR 变量或机器调用序列。

局部变量的读写转成 SSA；跨闭包共享的可写绑定使用抽象 cell。局部函数组保留相互递归和捕获身份，已知调用可以引用静态函数 ID。闭包是否分配、是否提升参数以及环境如何布局，由 MIR 分析决定。

本地退出变成带清理语义的控制流，跨函数退出保留动态有效期。退出令牌不能替换为可重用的栈地址。`unwind-protect` 的清理覆盖正常和异常路径，其自身退出可以覆盖原退出。多值以 bundle 传递，取主值与传递全部值分别表示。

## 表示与 ABI 降级

分析稳定后决定装箱、机器整数和浮点表示，选择闭包、cell、cons 与 rest 列表的存储。对象布局取自与 runtime ABI 指纹一致的目标描述。栈存储和标量替换遵守 [MIR 的身份与存储证明](mir.md#身份与存储证明)。

调用映射为现有 Lisp ABI：self、参数个数和参数、主值和值数，以及 context 中的其余多值。动态环境、special 绑定、catch、退出点和 cleanup 映射为 [ABI](abi.md) 中的条目和 handler。跨调用存活的对象必须有精确 roots，raw 位模式不得作为对象扫描。

分配降级保留 bump pointer 快路径与 runtime 慢路径，加入需要的 poll、写屏障和 GC 元数据。调试变量的值、位置和表示与源码身份关联，不能因闭包或拆箱变换留下过期位置。

## 常量和初始化

image 模式通过 literal ID 保持现存对象身份，安装阶段接管 roots。交叉编译通过常量对象图产生静态数据及必要的加载初始化。允许的常量合并按模式与语言契约确定，不能把 image 对象按内容合并。

`load-time-value` 在空词法环境转换，产生独立初始化单元与 root cell，按模块初始化顺序执行。不同编译结果的单元不因缓存而意外共享。定义的发布和加载副作用由 Lisp 安装层组织。

## 原语和调用点变换

Lisp 将 `%primop` 及受支持的语言原语归一化为有版本的操作描述；Rust 校验签名和效果，再选择具体实现。机器布局知识和快慢路径在 Rust 中集中维护。

数值的溢出慢路径、类型与边界检查、数组访问、`eq`/`eql`、cons 操作、已知函数调用及分支简化在 MIR 上实现。`append`、序列查找、常量类型检查和 CLOS 调用点特化可利用语义操作与依赖事实。语言编译器宏仍由 Lisp 展开，Rust 的变换不再次调用宏。

## KIR 到机器码

Rust 通过内存中的 KIR 结构交给 kiln-cg，KIR 文本保留为文件、诊断、FASL 和自举比对接口。KIR 已包含对象布局、GC 类型和低级控制流；kiln-cg 负责 Cranelift 构造、调用约定、异常表、栈图及目标代码。语法与现有接口见 [codegen.md](codegen.md)。

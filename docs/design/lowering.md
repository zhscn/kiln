# 降级：MIR 到 LIR

原生编译在 MIR 上完成语义分析与表示选择，随后由 `lisp/mir/lower.lisp` 退出 SSA，使用 `lisp/lower.lisp`、`lisp/values.lisp` 和 `lisp/primitives.lisp` 的发射工具构造 LIR。Rust 验证 LIR 并落实对象布局、机器调用约定、精确 roots 与动态环境条目，见 [lir.md](lir.md) 和 [compiler-protocol.md](compiler-protocol.md)。

## 证明与操作

发射器接收 MIR 的类型、多值、存储和机器表示事实，不再遍历 HIR 树推导这些性质。声明检查已经进入 MIR 的 CFG；证明不足时保留检查或调用通用入口。全局内建原语、类型测试、数组访问、序列搜索、槽缓存和构造器特化遵守调用点的策略及 `notinline`，具体证明边界见 [mir.md](mir.md)。

MIR 中的函数与区域各有独立编号。退出 SSA 时，块参数变为局部操作数，边实参通过复制传入后继；普通边无需传递块实参时直接跳到后继。需要
边复制或执行异常 landing 指令时在边上建立独立的 LIR 块。机器 double 值和装箱对象副本按实际用途保存。源码变量的位置来自 MIR 调试绑定，源码位置和宏展开来源沿用 HIR 的语义来源。函数、闭包捕获、共享 cell 及私有入口的布局由已验证的 MIR 单元决定。

MIR 发射器将各入口的捕获数量登记到模块声明。规范化使用这些声明，
在处理堆闭包和栈闭包的对应操作时检查分配形状。诊断构建器也可以从分配语句补齐
未显式声明的捕获数量。

## 参数与多值

参数协议先在 MIR 中展开为普通 CFG：保存入口实参、检查数量、求出缺失默认值、绑定 supplied-p 与关键字快照，并按顺序建立 special 绑定。发射器以 `receive-prefix` 提交位置实参目标和计数；Rust 在可能覆盖传递区的操作前保存它们。`rest-list` 提交后缀起点及已证明安全的候选栈 cons，Rust 选择整条列表的栈或堆构造并保护未读取的实参。

关键字快照的长度由编译期的描述符数量确定。短关键字列表在没有实参时共享只读的全缺省快照。入口从实际参数构造正规列表，扫描器可以直接读取每个 cons，只需检查最后一个键有无配对的值。扫描按描述符下标写入值和 supplied-p 槽，重复实参保留首次出现的值。入口用同一槽数直接读取快照，随后才求默认值。

主值和计数作为一组传递。跨调用需要保留的多值通过 `save-values`、`restore-values`、`push-values` 和 `values-list` 表达，由 Rust 维护载体、传递区和分配 roots。调用结果的未知计数和非局部退出的多值载荷保持运行期计数；`move-values` 将主值与计数一起复制到合流目标。接口和限制见 [abi.md](abi.md)。

## 动态区域与存储

MIR 的区域关系决定正常退出、本地退出和异常落地需要恢复哪些绑定与清理。发射器提交动态环境操作和 handler 后继，Rust 分配条目并实现展开。跨函数 block／tagbody 的闭包捕获堆令牌，堆对象不持有帧内部地址；`unwind-protect` 的 cleanup CFG 和继续展开规则见 [mir.md](mir.md)。

词法 cons、闭包和入口 rest 只有在 MIR 逃逸证明及调试可见性检查通过后才使用栈存储。`establish-stack-object` 初始化固定槽并登记连续引用字段，Rust 按 LIR 的存储形状建立精确 roots。证明不足时保留堆分配；对象布局和小对象分配快路径见 [gc.md](gc.md)。

同一 MIR 块内，`car`、`cdr`、`first` 和 `rest` 可以共享对同一 SSA 值的 cons 判断。首次读取在接收者既非 cons 也非 NIL 时发出类型错误。后续读取复用判断结果，并在 cons 路径上重新读取字段，因此能看到期间发生的字段修改。已有 cons 类型证明时，发射器直接读取字段。

独立 LIR 由 Rust 在入口保存参数、构造 rest 后安排 poll，并按 CFG 选择循环 poll；栈耗尽时调用当前 `%stack-exhausted`。MIR 的循环及动态区域验证保证源语义需要的 safepoint 和异常后继不会在发射时丢失。

## 固定角色入口

普通和 SETF 函数格的未定义占位对象、funcallable 转发及未设置目标时的错误入口由 Rust 生成。Lisp 按角色和 file/image 作用域声明所需入口；静态或动态占位对象提交其所属 symbol，funcallable 分配提交 rack。后端决定捕获字段、入口引用和初始调用目标。函数格的未定义检测使用 `undefined-function-p`，不比较代码地址。

## Runtime 服务

普通 runtime 服务提交 `runtime-op`，包含操作名、已求值对象、动态 handler 和源码位置。Rust 的闭合表定义调用名称、参数数量、签名和 safepoint 效果，补齐 imports，并为身份哈希保留缓存快路径。Lisp 发射与规范化使用生成的服务描述检查名称和参数数量，不声明这些函数的 ABI，也不选择哪些服务需要 safepoint trampoline。生产路径的帧指针操作表达为后端 token，不在 Lisp 中构造地址。

GC、packet 编码、编译失败诊断和跨栈 Lisp 调用可能 safepoint 或覆盖传递区；独立 LIR 验证器使旧多值视图失效并传播异常边。其余服务遵守当前 runtime 的 NoSafepoint 合同，保留传递区内容。运行期编译的批量快照、代码安装和 literal 绑定期间不调用 Lisp。

## 数值与错误分派

整数和实数 runtime 原语提交具名 `numeric-op`。操作码、调用签名、context 参数和返回个数在 Rust 中选择，除法余数按 runtime 约定转换成多值结果；Lisp 不读取余数所在的传递区槽。普通数值快路径由 MIR 类型和区间事实选择，后端接口不重新进行语言类型推导。

fixnum 除以正的二次幂时，`floor` 用算术右移，`truncate` 在负被除数可能有余数时先做舍入修正。除数为 2 时，发射器可以沿 SSA 定义识别两个相差奇数的整数相乘。这种乘积一定是偶数，商直接右移，需要余数时返回 0。乘积仍经过原有的求值和溢出检查。

整数 `mod` 的除数为正的 fixnum 常量时，MIR 将余数限制在 0 到除数减 1。被除数已经证明为 fixnum 时可直接使用机器运算，只证明为整数时先检查表示，bignum 走通用 `mod`。机器路径对二次幂使用位掩码，其余常量用机器余数。机器余数为负时加上除数，得到 Common Lisp 要求的非负结果。

当 MIR 证明被除数是 fixnum、除数是固定的正二次幂时，`floor` 和 `truncate` 可直接计算商，并把商的区间传给后续运算。算术右移给出向下取整的商，`truncate` 对可能为负的输入先加偏移，再右移得到向零取整的商。需要第二返回值时，发射器用原被除数减去商与除数的乘积计算余数，并按普通多值规则传递。
二元 `/` 用掩码判断低位是否为零。能整除时用同样的算术右移返回 fixnum，
否则调用有理数除法，保留精确比值。

可恢复错误提交 `signal-error`，包含语义错误码、已求值对象、动态 handler 和源码位置。Rust 查找当前 `%runtime-error` 定义，安排 Lisp 调用，并在定义不可用或返回时调用 fatal runtime 入口。该操作终结当前块；条件系统引发的非局部退出沿原有 handler 展开。

## 加载期初始化

HIR 词法准备收集 `load-time-value`，MIR 为其建立独立初始化函数和 root cell。模块 init 在包含它的顶层形式之前按顺序执行初始化一次；引用处只读取该 cell。运行期 image 的 literal 表保留原对象身份，原生编译请求和安装过程保护所有 literal roots。

## 常量

交叉编译时，槽存储数组的类和布局由目标 image 在初始化阶段建立。引用通过
`defconstant` 定义的这类数组时，HIR 求值使用编译期对象，MIR 生成对符号值的读取。
目标端的 `defconstant` 初始化式构造数组，供后续引用共享。

- fixnum、字符、single-float、NIL、T 是立即数或静态对象。
  后端可从赋值证明临时值的 fixnum 标签位始终为零。检查溢出的加减和乘法
  也能参与这个证明，因为结果按机器字长回绕时最低位不变。只有所有赋值都
  能证明标签位为零时，后端才把该临时值从 GC 栈图中省去。调试器需要的栈槽仍会生成。
- symbol 是静态 symbol（或运行期 image 里的符号，见 [eval-compile.md](eval-compile.md)）。
- cons 树、字符串、向量、bignum、ratio、double-float 作为静态数据输出，GC 不移动也不扫描。静态字符串常量按内容合并，cons 常量按 car 和 cdr 合并。编译进活 image 时，literal 表保留原对象身份。
- MIR 从 SSA 定义证明函数名为常量后，可将 `(setf fdefinition)` 调用降级为函数对象检查、函数 cell 写入和定义变更通知。
- `defconstant` 的常量在编译期登记进编译期环境，引用处直接编译成值。

## 原语和 `%primop`

**原语**（`lisp/primitives.lisp`）是编译器直接展开的 CL 函数：fixnum 的 `+ - * 1+ 1- < > <= >= = /= zerop plusp minusp`、`logand`、`logior`、`logxor`，字符比较（`char= char/= char< char> char<= char>=`），`eq eql null not`，类型谓词，cons 操作（`cons car cdr first rest second third cadr cddr endp rplaca rplacd list list*`），`svref`、`(setf svref)`、`length`，`values`、`values-list`、`apply`、`funcall`、`nth`、`nthcdr`、`fdefinition`、`symbol-value`、`boundp` 及其 setf，以及 `kiln.sys` 里的测试用原语。

- CL 的函数不能被重定义（CLHS 11.1.2.1.2），所以内联是合法的。
- 数值原语内联 fixnum 的快路径；参数不是 fixnum 或者溢出时调用 kernel 的 `two-arg-+` 等函数。`floor`、`truncate`、`ceiling`、`round`、`mod`、`rem` 对两个 fixnum、`ash` 对 fixnum 也有内联的快路径（KIR 的 `sdiv`、`srem`、`shlv`、`sarv`），不调用 runtime。比较原语接受任意个参数，按相邻两两比较。
- `svref`、`length` 对 simple vector（`length` 也对字符串）内联，其他情况调用 kernel 的函数。
- `eql`：两个不同的一般对象，只在第一个是 bignum、ratio、double-float 时才调用 kernel 的 `eql-slow`，其他直接返回 NIL。
- 原语被当作函数对象使用时（`#'car`），读 symbol 的函数 cell：kernel 用 `(defun car (x) (car x))` 这种写法给每个原语一个真正的全局函数。
- 单参数的 `print` 是给没有流的早期测试用的原语（带流参数的 `print` 调用打印器的 `print`），直接调用 runtime 的打印函数（先打印对象再换行，不经过 `*standard-output*` 和 `print-object`）。编进运行中 image 的代码不用它。

**`%primop`**：`(kiln.sys:%primop :名字 参数...)` 是 kernel 代码访问底层操作的唯一入口（单一入口加关键字操作码，和 SICL 的做法一样）。它对前端来说是普通的函数调用，HIR 转换验证第一个参数是 keyword 字面量，MIR 发射时查 primop 表（`*primops*`），展开成内联代码，所以前端不需要改。例如分配和读写实例、`:identity-hash`、`:hash-mix`、`:fd-read`、`:sys`、`:jit`、浮点的位模式。

## 浮点控制与未装箱算术

MIR 保留简单数组声明中的形状及受支持的元素类型，包括单精度、双精度和以对象向量存储的 fixnum 范围。成功检查后的 SSA 值可以满足后续兼容的声明。整数维度和字面选项也能证明 `make-array` 创建的是这种简单向量。对于有界整数元素类型，编译器与数组库使用同一份升级顺序，按能够容纳整个请求区间的首个类型决定存储表示。单下标读取使用专用入口，写入还要求证明待写值符合升级后的元素类型。秩已知为一时，入口用存储向量长度检查下标。否则先检查数组秩，再用维度检查下标。读取的元素类型可传给后续数值运算。

带字面浮点元素类型和长度的 `vector` 类型测试先用类标记确认槽布局，再读取实际维度。位移向量通过数组协议取得维度，类标记不匹配时走通用类型系统。类型测试使用数组维度，填充指针只影响序列长度。

`elt` 及其写入在 kernel 内直接使用同一份浮点向量布局。数组层初始化时发布布局，kernel 先验证实例类标记，再检查位移、秩、下标和写入值。成功时用填充指针或实际维度作序列边界，直接访问存储向量。布局尚未发布、向量有位移或检查失败时，继续走通用序列入口。

简单向量的底层存储在对象创建后固定。对有已知简单特化向量的函数，发射器扫描指令，
沿已有 SSA 事实统计可以共享存储的访问。同一已证明对象有多处访问，或单处访问位于循环内时，发射器可在
参数或捕获值的入口准备阶段取得存储向量，包括通过声明检查后才建立类型证明的情况。
已知只返回一个值的生产调用也是可用的位置。
这个调用的位置必须允许它覆盖 ABI 的多值区。后续读写共享 GC 可见的存储向量及其长度，
只在访问点检查下标。秩未知时，入口为一维数组缓存存储及长度，其他秩记录零长度。
零长度与下标越界走同一条慢路径，由原数组入口报告错误。
向量长度是非负 fixnum。下标确认为 fixnum 后，一次无符号比较同时拒绝负下标和不小于长度的下标。
已知秩为一且尺寸固定时，发射器用该尺寸作为下标检查的上界，省去读取存储向量长度。如果索引的整个整数区间都在边界内，发射器直接读写已取得的存储向量。对于静态可确定的 `array-dimension`，编译器将尺寸作为精确整数传给后续运算，同时保留实参求值。
简单向量的下标检查失败时，慢路径会发出错误。沿正常返回路径，降级器按 SSA 下标
记录已验证的存储或静态上界，后续访问可以复用同一存储的检查。若检查给出了静态上界，
尺寸不小于该上界的其他固定向量也可以复用结果。

当不同分支传入不同下标时，降级器先沿每条控制流边将相应的证明传给目标块参数。
汇合点只保留每条可达入边都能证明的事实。若不同入边证明了不同的静态上界，
取其中较宽的上界，确保每条路径都满足它。循环入口和回边也按这个规则汇合。
因此，回边上的检查可以证明下一次迭代收到的下标，但首次进入循环仍须从入口边
取得同样的证明。重新执行下标定义或后备存储查找时，旧值的证明随之失效。
控制离开普通跳转或条件分支时，降级器保守地清空传往后继的证明。

只证明操作数是 double-float，不能证明当前采用默认舍入模式。MIR 降级在
浮点四则运算处读取 context 中的动态控制状态；显式控制区域调用 kernel 的
统一受控运算，再恢复未装箱结果。默认路径直接计算 binary64，非有限结果转入
同一检查路径，以区分输入无穷、无效运算和有限参数上溢。该分支移除结果位模式的
符号位，再将指数域符号扩展。全一的指数扩展为 −1，可直接与机器指令的立即数比较。
负号与 ABS 只修改
符号位，不需要数值舍入。调用慢路径时，装箱参数遵守正常调用和 GC 栈图协议。
多个 double-float 操作数按原有的左结合顺序计算。每一步保留舍入和异常检查，
中间值在机器表示中传递。一次多参数运算的快路径复用最初读取的动态控制状态。
慢路径返回后，在还有运算步骤时重新读取该状态，以反映调用期间的修改。
双精度数组的底层存储也使用 binary64。特化读写直接传递机器表示，只有通用入口或需要 Lisp 对象的使用点才装箱。发射器把 binary64 值直接交给装箱指令，后端在写入对象时保留原位模式。
已知两个操作数均为 single-float 时，后端从立即数提取 binary32 位模式并在该精度下运算。
发射器仍检查动态浮点控制和非有限结果，需要时调用同一个受控运算入口。
已知各操作数是有理数或具体浮点格式时，MIR 将参与运算的最高浮点格式传给后续操作，
例如用 single-float 运算的结果写入同元素类型的简单数组。
带双精度样例的 `float` 对已证明的 fixnum 使用机器转换，直接产生未装箱结果。
编译期区间能证明精确转换时，直接发射机器转换。区间未知时，运行期用可回绕的字加法把精确区间移到最小有符号字处，再用一次有符号比较确认是否落在区间内。只有可能需要舍入的大 fixnum 才读取动态控制状态。
未证明整数属于 fixnum 时，生成代码检查实际表示，其他数值仍交给普通 `float`。单参数 double-float 的 `/`
在默认路径计算 binary64 的倒数，受控舍入和非有限结果走普通除法入口。

一元浮点整除函数的主值保留输入的浮点格式，余数继续通过多值协议返回。
双精度数除以整数 1 做 `truncate` 时，如果商能放入 fixnum，运行期直接以机器浮点数计算商和余数，避免构造任意精度整数。其余输入使用通用数值路径。

通用实数算术先检查操作数的表示。两个操作数均为双精度时，复用 MIR 的机器值
算术和受控舍入回退。其他数值走通用运算，并检查结果的浮点指数。单精度位模式和
双精度高位字都可用 fixnum 表示，指数掩码使用 fixnum 位运算。结果为无穷或 NaN
时进入受控算术处理。

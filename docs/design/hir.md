# HIR：Lisp 语义表示

HIR（high-level IR）是宏展开和环境解析后的语义树，由 Lisp 构造并求值。它承接 CST 的源码信息，固定绑定与声明的含义，为解释执行和 Rust MIR 构造提供共同输入。总体分工见 [编译器架构](compiler.md)。

当前 HIR 使用 `lisp/hir/` 中的原生结构对象和整数 kind 分派；类型传播、逃逸分析和 KIR 降级也仍在 Lisp 中。目标架构将这些优化与降级迁往 Rust，HIR 保留语言语义所需的处理和求值能力。结构对象的字段布局属于 Lisp 内部实现，跨语言协议不直接暴露它们。

## 语义实体

节点引用显式的变量、函数和退出点实体。变量引用按绑定身份解析，不靠符号名字重新查找；同名遮蔽、special 声明和词法作用域在树中已经确定。函数记录参数协议、局部函数组、自由变量、可写捕获及源码身份。可写捕获表达共享存储的语义，不预先规定用 cons cell 或哪种闭包布局。

`block`、`return-from`、`tagbody` 和 `go` 指向词法退出点；跨函数引用与本地引用保持可区分。`catch` 和 `throw` 保留动态 tag 求值。`unwind-protect`、special 绑定和 `progv` 保留动态范围、求值顺序和清理语义。

树明确区分主值消费和全部多值传递，保留零值与一个 NIL 的差别。函数体、条件分支、退出和清理不得在语义转换时丢失多值。参数初始化、赋值、函数操作数与实参按语言规定的顺序执行。

## 声明、类型与策略

声明按绑定和词法作用域保存。原始类型说明用于诊断，展开后的受支持描述用于分析；未知描述作为不透明检查保留。`optimize` 策略、`inline`/`notinline` 和调试可见性随作用域传递。声明引入的检查及其位置是语义契约，不能因为后续表示变化而遗漏。

类型展开器和编译器宏在 Lisp 中执行，其依赖交给定义失效机制。类型推导、区间固定点、函数摘要和机器表示选择属于 MIR；HIR 导出的是已知事实和检查义务，不是需要 Rust 再查询的环境。

## 求值器

HIR 求值器留在 Lisp 世界，执行宏函数及编译期辅助函数，也提供原生编译器尚未启用时的解释执行。它与原生路径共享绑定、参数协议、声明和退出语义，不要求运行可选的 MIR 优化。

求值器的闭包和词法环境属于执行状态；导出的 HIR 描述程序语义。编译期间出现的函数对象不能作为任意宿主闭包传给 Rust，必须是可引用的 literal、已解析函数体或保留的动态调用。

## 常量与来源

每个节点保留源码范围和可用的宏展开来源。缺少直接位置的展开节点继承合理的外层位置，诊断仍可定位原始形式。名字用于展示；确定性编号与名字分开。

常量引用保持对象身份和共享关系。image 中的现存对象经 literal 表保持存活；交叉编译使用可移植对象图及必要的加载初始化描述。`load-time-value` 保留独立的初始化身份和顺序，不能作为普通常量折叠而跨编译结果共享。

## 导出约束

导出前不再有待展开宏、未解析词法名字或隐含的编译环境查询。导出包含嵌套函数、绑定、退出点、策略、来源、常量引用、归一化原语和依赖。内联候选在定义环境中完成语义转换，是否使用候选由 Rust 决定。

导出以批量、带版本的数据记录进行；不序列化 CST、Lisp 环境、结构对象内存或原始堆指针。具体格式与生命周期见 [编译协议](compiler-protocol.md)。控制流和 SSA 的构造见 [MIR](mir.md)。

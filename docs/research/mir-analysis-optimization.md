# MIR 分析与原生编译成本

日期：2026-11-17。

相同 kernel 输入的原生编译模块时间从原始 MIR 的 24.76 s 降至 8.01 s，
六模块后端总时间从 44.67 s 降至 35.44 s。历史 HIR 的 kernel 为 2.03 s，
因此这些优化减少了回退成本，尚未恢复历史 HIR 的吞吐量。

HIR 分析移到 MIR 后，慢的原因包括分析失效范围过大、固定点算法重复扫描，
以及编译器自身生成的代码包含大量通用类型判断和多值装箱。仅把分析放到
CFG 上并不会自动减少这些工作：若每个函数改写都重算整个单元，迁移后反而
会把局部变换放大成反复执行的跨函数分析。

本文沿用 [HIR → MIR 对照测量](mir-compilation.md) 的历史输入和测量边界，
补充分析复用、SSA 构造、类型证明和多值表示的成本。历史 HIR 的 eval 模块
包含旧编译器，跨版本模块表用于观察整体成本；严格相同输入的原生 kernel
编译用于比较编译器吞吐量。

## 测量条件

机器为 Ryzen 9 7940HS，8 核 16 线程，开启 boost；SBCL 为 2.6.10-1.fc45，
Cranelift 为 Cargo.lock 固定的 0.137.1。CPU 密集测量串行执行。原生编译
固定 8 GiB 堆，预热一次后测三次，取中位数。模块阶段包括前端、MIR 降级
和 LIR 输出；进程时间还包括启动和初始化。

后端测量固定同一个 release `kiln-cg`，逐模块预热一次、测三次，合计各模块
中位数。后端总时间包含解码、LIR 降级、调试信息和目标文件输出；
`machine_seconds` 只表示 Cranelift 机器码生成。文件大小包含常量和调试
数据，代码规模另外按规范化 LIR 中的基本块、变量和语句计数。

## 重复分析的来源与复用边界

谓词、条件边、内联和私有入口变换原先逐函数修改后再次查询单元摘要。
每次查询都可能重做参数类型、返回值、函数身份和 cell 的固定点分析。
变换现在先在稳定快照上收集一批互不依赖的计划，再统一执行；下一轮才查询
新的摘要。函数版本和单元 epoch 分别控制局部与跨函数分析，缓存命中不再
逐次构造整个单元的函数版本向量。

固定点求解使用依赖工作队列。参数别名只唤醒读取该别名的参数，类型和函数
身份只沿调用、返回、捕获和 cell 读写依赖传播。验证器仍从新图验证结构，
但同一轮验证共享函数身份和只读缓冲区视图；新算出的 CFG 和绑定区域可供
紧随其后的优化使用。视图只在稳定修订范围内共享，任何改写都关闭旧视图，
独立验证也重新建立视图，因此同长度的原地修改不会被缓存遮蔽。

构造 SSA 时，原先每个块都先建立所有词法绑定的参数，然后靠后续化简删除。
现在先记录临时绑定引用，从实际用途沿入边追踪需求，最后只物化需要的参数。
退出 SSA 的并行复制按依赖顺序发射，只有环需要临时变量；小复制集合采用
有界线性扫描，大集合才建立索引。未使用且无副作用的值加载在分配 LIR 局部
变量之前删除，可能报错的检查和有副作用的操作仍保留。

对象图字段查询原先对每个接收者集合扫描完整字段表。接收者通常只有一个
本地分配点，或只有表示外部对象的位零，整表扫描因而重复处理大量无关项。
字段读取、写入和逃逸传播现在只访问集合中选中的本地字段，保持未知对象、
rest 堆回退和传递逃逸的保守规则。

## 类型、poll 与装箱

元数据槽的类型现在同时服务宿主和目标编译器。结构 getter 的结果具有槽
声明的类型，构造和写入执行相应检查；继承槽的约束合并后继续成立。MIR
可因此证明编号和索引操作的类型，不必在每次读取后重新调用通用谓词。

原生采样还发现大量原子 `unsigned-byte` 检查。该类型包括任意大的非负整数，
原先有限位宽区间一旦 widening 就退回一般整数，随后的检查无法消除。
类型域现在保留“非负整数”事实；无界检查用整数判断和符号判断内联，包含
bignum。它不等同于 fixnum，也不证明任何有限位宽。有限宽度和不确定符号
仍保留各自的检查。

多值的完整需求与堆持久化需求原先混在一起，返回路径上的合流也可能建立
列表载体。现在分析分别追踪两种需求，只在证明当前多值区仍属于该结果时
直接转发 primary/count 视图。调用、分配、poll、动态退出或其他载体恢复
会撤销相应证明；必须跨越这些边界的值继续保存到堆载体。并行边复制先保护
多值视图，再写目标变量，防止复制顺序覆盖尚未读取的数据。

poll 由覆盖所有 CFG 环的 DFS 回边目标承担，函数入口检查和原语内部循环
的 poll 继续保留。这样避免在一个强连通分量的每个块插入慢路径。高调试
策略下，仅未被源码变量或调试器观察的浮点临时值保持拆箱；命名变量、参数
和合流值继续遵守对象根和调试可见性要求。

## 共享 base 的回退预算

`bench/baselines/shared-base.json` 固定六个工作负载、执行顺序、源码校验和和
堆配置。`tools/bench-tests.py` 串行执行一次预热及多次缓存命中测试，分别
记录 compile-file、加载和 64 MiB GC 压力加载。`--rebuild-base` 另测冷 base
构建和快照；已有 Cargo 与 SBCL FASL 缓存保留。

磁盘预算覆盖共享 base 与选定测试的保留产物，同时记录逻辑大小和实际分配
大小，硬链接去重，符号链接不跟随。整个工作目录另行报告，避免其他测试
产物污染固定预算。比较时拒绝不同输入、顺序或堆配置；默认允许 10% 波动，
超出后返回失败。更新基线前先与旧基线比较，保留可重复的摘要，逐次样本和
日志留在忽略的构建目录。

ANSI 验证使用同一套件版本和 native 配置。设置 `ANSI_REPORT_NAMES=1` 后，
每组日志包含失败名称及禁用测试的 note；`tools/check-ansi-baseline.py DIR
GROUP...` 要求所有指定组有完整结果，逐项比较 `tests/ansi-baseline.json`。
总失败数相同但失败名称、跳过项或跳过原因改变，也会返回差异。

## 测量结果

以下为字段位集合遍历、分析复用和表示优化后的同机测量。原始 MIR 的历史输入和后端设置与前述报告一致。

| 模块 | 原始 MIR LIR（MiB） | 优化后 LIR（MiB） | 原始 / 优化后后端（s） | 原始 / 优化后 Cranelift（s） |
|---|---:|---:|---:|---:|
| kernel | 20.26 | 19.27 | 1.765 / 1.310 | 0.166 / 0.102 |
| clos | 176.06 | 170.60 | 16.518 / 13.351 | 1.257 / 0.832 |
| frontend | 5.28 | 5.16 | 0.460 / 0.354 | 0.051 / 0.033 |
| eval | 153.44 | 151.72 | 25.346 / 19.962 | 1.438 / 0.833 |
| compiler | 6.24 | 6.24 | 0.534 / 0.431 | 0.048 / 0.025 |
| build | 0.43 | 0.42 | 0.046 / 0.036 | 0.013 / 0.010 |
| 合计 | 361.70 | 353.40 | 44.67 / 35.44 | 2.97 / 1.83 |

相同 kernel 输入的原生编译阶段中位数为前端 1.186 s、降级 3.433 s、输出 3.393 s，合计 8.012 s；进程中位数 12.136 s。原始 MIR 阶段合计 24.763 s，历史 HIR 为 2.031 s。优化降低了成本，仍未恢复历史 HIR 的吞吐量。

优化后规范化 LIR 共 3,193,253 个变量、3,977,305 条语句、5,545 个显式 poll。原始 MIR 分别为 3,305,708、4,218,416 和 149,032。基本块和函数数量受实现自身新增函数影响；常量和调试数据也占据包体，文件字节数不能直接代表执行路径规模。

固定共享 base 工作负载的缓存命中中位数为 6.588 s，旧基线为 10.113 s；选定产物逻辑占用 325.39 MiB，实际分配 325.47 MiB。冷 base 构建 68.182 s，快照 2.838 s。冷构建使用已有 Cargo 与 SBCL FASL 缓存，不能与从空缓存安装依赖的耗时混用。
